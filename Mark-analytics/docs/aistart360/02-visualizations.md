# AIStart360 — Visualization System

> Catalog of chart types and interaction patterns for the Market Intelligence module. Frontend chooses the chart; **backend's job is to deliver the data in a shape the chart expects**, with reasonable defaults that prevent cognitive overload.

## 1. Principles

1. **Progressive disclosure**: first the headline number, then chart, then drill-down. Never dump 30 series at once.
2. **One question per chart**: each chart answers a single question stated as its title.
3. **Hierarchical color**: status colors (red/yellow/green) reserved for signals; categorical colors quiet (≤ 6 hues max per chart).
4. **Server-aggregated**: all aggregations happen in SQL; frontend just renders. No 10k-point line charts.
5. **AI captions**: every chart can optionally include a 1-sentence AI-generated caption ("Industry X grew 23% YoY, mostly in Q3 — see drill-down"). On-demand, cached 24h.
6. **Export-friendly**: every chart endpoint also serves `?format=csv` and `?format=png` (SSR via headless renderer in Phase 2).

## 2. Chart taxonomy

| Chart | When to use | Backend shape | Endpoint pattern |
|-------|-------------|---------------|------------------|
| **KPI card** | Single number + trend | `{value, prev, change_pct, sparkline:[...]}` | `/trends/kpi/{key}` |
| **Line / area** | Time series | `{series:[{name, points:[{t, v}]}], baseline?}` | `/trends/series/{key}` |
| **Stacked bar** | Composition over time | `{periods:[t], stacks:[{name,values:[v]}]}` | `/trends/stacks/{key}` |
| **Bar (categorical)** | Top-N | `{items:[{label, value}]}` | `/trends/top/{key}?dim=...` |
| **Heatmap** | 2-dim density (region × industry) | `{rows, cols, matrix}` | `/trends/heatmap/{key}` |
| **Sankey** | Flow (industry → industry, region → region) | `{nodes, links:[{source,target,value}]}` | `/trends/flow/{key}` |
| **Sunburst / treemap** | Hierarchical breakdown | recursive `{name, value, children}` | `/trends/hierarchy/{key}` |
| **Radar** | Multi-dim comparison (5–8 axes) | `{axes:[name], series:[{name, values:[]}]}` | `/companies/{id}/radar` |
| **Scatter / bubble** | Two metrics + size | `{points:[{x, y, r, label}]}` | `/trends/scatter` |
| **Network / graph** | Relationships | `{nodes, edges}` (Cytoscape format) | `/companies/{id}/graph` |
| **Cluster map** | Geo-bound clusters | GeoJSON + cluster metadata | `/trends/geo/{key}` |
| **Market matrix** | 2×2 (e.g., growth × market share) | `{quadrants, points:[{x, y, label}]}` | `/trends/matrix/{key}` |
| **Timeline** | Events by date | `{events:[{at, kind, label, payload}]}` | `/companies/{id}/timeline` |
| **Forecast fan** | Time series + uncertainty band | `{historical:[{t,v}], forecast:[{t,p50,p10,p90}]}` | `/forecasts/series/{id}` |
| **Comparison panel** | N companies side-by-side | array of `CompanyDetail` slim | `/companies/compare?ids=...` |
| **Scenario simulator** | Sliders + recomputed outcome | interactive — frontend sends params, backend re-runs forecast | `POST /forecasts/{type}/simulate` |

## 3. Common interactions

- **Hover**: tooltip with formatted value + AI-supplied unit/context.
- **Click**: drill-down (segment → list of underlying companies/tenders).
- **Brush**: time-range select on line charts → other charts filter in sync (cross-filter pattern, frontend state).
- **Compare toggle**: switch a single-series chart to multi-series by selecting peers (uses semantic lookalikes from backend).
- **Annotate**: user adds note pinned to a data point → saved per-user, optional team-share.

## 4. Backend response shapes (canonical)

All charts return `{data: <shape>, meta: {generated_at, source_count, ai_caption?: str|null, cache_ttl: int}}`.

`ai_caption` populated only if `?explain=true` query flag. Generated by `Task.ANOMALY_EXPLANATION` or `Task.SUMMARIZE_NEWS` depending on chart type. Cached separately from data.

## 5. Dashboard composition

The default Market Intelligence dashboard ships **6 widgets** (preventing overload):

1. **Industry health KPI** — top-level: total companies, % active, growth YoY in selected industry.
2. **Top regions** — bar chart, top 5 regions by company count in industry.
3. **Trends line** — new company registrations last 24 months in industry+region.
4. **Competitive matrix** — 2×2 with selected company + 8 peers (size × growth).
5. **Recent signals** — feed of events (M&A, large tender wins, executive moves, large hires).
6. **AI insight card** — 2-sentence AI explanation of the most notable shift in the last 30 days.

Power users (Pro tier+) can rearrange widgets via drag-and-drop; layout persisted per user (`user_dashboard_layouts` table). MVP: hardcoded.

## 6. Backend support contract

Each chart endpoint:

- Accepts the **same filter taxonomy** as `/companies` (delegated to `app.filters.registry`).
- Returns `Cache-Control: max-age=300` for aggregations.
- Stamps `X-Data-Freshness: <timestamp>` so frontend can show "data as of …".
- Errors return envelope with `error.code = 'CHART_DATA_UNAVAILABLE'` when underlying SQL would take > 3s — frontend shows graceful "computing…" then polls.

## 7. Performance budgets

| Chart | p95 latency target |
|-------|---------------------|
| KPI, top-N, line | < 250 ms (cached) / < 1.5s (cold) |
| Heatmap, Sankey, geo | < 600 ms (cached) / < 3s (cold) |
| Forecast | < 2s (cold; cached after) |
| Graph | < 800 ms |
| Compare | < 500 ms |

Cold > 3s → background materialized view via Arq nightly refresh.

## 8. Frontend library recommendation

Frontend repo concern (separate). Suggested stack:
- **Tremor** for KPI cards + simple charts (sane defaults).
- **Recharts** or **Visx** for custom.
- **Cytoscape.js** for graphs.
- **Mapbox GL** or **MapLibre** for geo.
- **Apache ECharts** for heavy interactivity (Sankey, complex composites).

Frontend agent picks specifics; backend stays chart-library agnostic.
