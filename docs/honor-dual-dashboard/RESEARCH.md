## Почему пользователь не видел Miro-like Journey

Канонический `JourneyWorkspace` уже заменил старую вертикальную страницу в
`599e0535`. Однако на desktop `conversationFirst` полностью скрывает canvas до
стадии `ready`, а кнопка открытия доски передаётся в `ChatDock` только после
подтверждённой цели. Следовательно, пользователь на стадии постановки цели
видит только чат и обоснованно воспринимает это как отсутствие доски.

Исправление: оставить разговор первым экраном, но дать владельцу Store явную
кнопку открыть read-only Точку A/доску до подтверждения Точки B.

Между базовой таблицей и P&L есть допустимое округлённое расхождение `−0,75 ₸`:
базовая `revenue − cost` даёт валовую прибыль `22 395 621,00 ₸`, а P&L сообщает

delta и использует сообщённую P&L-прибыль для точной EBITDA. Бонусы и списания
не вычитаются повторно, поскольку входят в расходы периода.

Формульные GP/margin/EBITDA нельзя принимать как доверенные input cells.
Парсер должен принять только базовые независимые числа и детерминированно
пересчитать производные значения.

Такие файлы исключены из Store-контура полностью: в dashboard разрешены только
агрегированные бизнес-факты без клиентов, счетов, телефонов и иных PII. После
приёмки владельцу следует закрыть публичный доступ к папке Drive.

## Дефекты текущего контракта

1. `StoreOverview` содержит только один `period` и один `metrics`.
2. Loader выбирает один последний operational month.
3. Наличие июльского sales run полностью отключает MyHonor для всех дат.
4. `asOf` смешивает публикации продаж, прайса, остатков и sync каталога.
5. `MyHonor · live` выводится без доказательства живого watermark.
6. Месячная история и P&L из Drive не имеют normalized published storage.
7. Store dashboard статичен, Journey finance facts повторяют тот же один месяц.
8. Нет authenticated Store/Journey E2E, доказывающего одинаковые числа.

## Выбранное решение

- расширить `StoreOverview` версионированным analytics DTO;
- выбирать источник отдельно для каждого календарного окна;
- хранить исторические финансовые месяцы в отдельном owner-scoped published
  fact layer с RLS и атомарной service-only публикацией;
- сделать workbook preview-first и идемпотентным;
- показать один DTO в обычном Store и в каноническом Journey;
- сохранить legacy поля до завершения миграции клиентов;
- отсутствие новой таблицы обрабатывать как partial fallback, без падения Store.
