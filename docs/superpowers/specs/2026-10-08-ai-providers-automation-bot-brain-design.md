# ИИ-провайдеры, автоматизация агентов и «мозг» Telegram-ботов — дизайн

Дата: 2026-10-08. Утверждено владельцем в чате (подход 1 «Единый мозг бота» + авто-провайдеры + уведомления об агентах).

## Контекст (факты на 2026-10-08)

- Прод: провайдеры `alem` (Alem Plus, 1 ключ), `o66krtxb5ti0mjr` (Alem LLM, 8 ключей: Qwen, Alem LLM, KazLLM, GPT OSS, Embedder, Reranker, Speech-to-Text, Kaz Speech-to-Text), `openrouter` (без ключа). В `ai_models` 4 строки, у всех `credential_id = NULL`; маршруты chat light/standard/premium → `AlemLLM`, embeddings → `Embedder`, rerank → `Reranker`.
- Alem выдаёт ключ на модель. Роутер (`lib/ai/providers/router.ts keyFor`) берёт первый включённый ключ провайдера для любой модели без `credential_id`.
- Без маршрута / при нерабочем маршруте / при явной модели, которой нет в справочнике, роутер падает в OpenRouter (`fallback`) → `NO_API_KEY`.
- Нет переключения на другого провайдера при сбое.
- ИИ-слой не поддерживает вызов инструментов; аудио нет; картинки — только в OCR (`chat_vision`).
- Боты обрабатывают апдейт синхронно (`maxDuration = 60`), свободный текст → приветствие; голос/фото/документы не принимаются.
- Ручной запуск агента-этапа диагностики («Сбор данных») из GIGA падает `NO_SESSION`.

## Часть A1. Провайдеры: обнаружение, автомаршрутизация, переключение

1. **Обнаружение моделей.** Для каждого включённого ключа: `GET {base_url}/models` с этим ключом → список id. Для каждого id upsert `ai_models` (provider, model_id, capability по эвристике имени, `credential_id` = этот ключ, `discovered_at`, `source = 'discovered'`). Модели, заведённые вручную, не трогаются (кроме привязки ключа, если `credential_id` пуст и модель найдена ровно у одного ключа). Эвристика capability: `embed` → embeddings; `rerank` → rerank; `whisper|stt|speech|asr|transcri` → transcribe; `ocr` → ocr; `vision|vl` → chat (+ флаг vision); иначе chat. Запуск: после добавления/замены/проверки ключа, кнопкой «Обнаружить модели» в GIGA, кроном раз в сутки. Если `/models` недоступен — ключ остаётся рабочим, модель можно завести вручную.
2. **Новые возможности (capability):** `transcribe` (распознавание речи, OpenAI-совместимый `/audio/transcriptions`), флаг `supports_vision` у модели. Миграция **107**: расширить CHECK capability, колонки `ai_models.source`, `discovered_at`, `supports_vision`, `supports_tools`, `tier_hint`; таблица/колонки здоровья не нужны (здоровье — в памяти).
3. **Автомаршрутизация** (`resolveCandidates(capability, opts)` → упорядоченный список целей):
   1. маршрут из `ai_routes` (если рабочий);
   2. явная модель вызова, если она есть у провайдера с ключом;
   3. любая рабочая модель этой capability у любого включённого провайдера с ключом (для chat — с подходящим `tier_hint`, затем любая), здоровые раньше сбойных;
   4. встроенный OpenRouter (если есть ключ).
   `resolveTarget` остаётся (возвращает первого кандидата) — обратная совместимость.
4. **Переключение при сбое**: `chatCompletion` / транскрипция / vision пробуют кандидатов по очереди при 401/403/404/408/429/5xx/таймауте/сетевой ошибке; сбойная цель помечается «нездоровой» в памяти на 5 мин (circuit breaker). Каждая попытка пишется в ledger как сейчас. Для **embeddings** переключения нет (векторы разных моделей несовместимы) — только назначенная/единственная модель.
5. `hasLlmKey()` / `hasOpenRouterKey()` = есть хотя бы одна рабочая chat-цель (маршрут или обнаруженная модель).
6. **GIGA «Провайдеры и ключи»**: у ключа — список найденных моделей и время обнаружения; кнопка «Обнаружить модели»; блок «Кто отвечает сейчас» (цель по каждой capability/tier, здоровье, последняя ошибка).
7. **Ручной запуск агента-этапа**: этапы диагностического конвейера не запускаются вручную; вместо них — «Запустить диагностику компании» (создаёт сессию). Ошибка `NO_SESSION` в UI — человеческим текстом.

## Часть A2. Автоматизация и агент-уведомитель

1. **Уведомления об агентах в админ-боте** (и ленте GIGA): задача запущена / завершена / упала / исчерпала попытки / ждёт одобрения — сотрудникам с `agents.view`, по уровням уведомлений (INFO/WARNING/CRITICAL) и mute, с кнопками «Открыть», «Повторить», «Отменить» (через подтверждение и аудит). Анти-спам: группировка — не больше одного сообщения о старте на задачу; массовые старты сворачиваются в сводку.
2. **Автоматизация** (системные настройки, тумблеры в GIGA, по умолчанию безопасные значения):
   - авто-повтор задач, упавших по временной причине (модель недоступна/таймаут), с экспоненциальной задержкой — уже частично есть в раннере, довести и показать;
   - авто-запуск диагностики компании при событиях (анкета завершена, документ обработан) — только если не запущена сегодня;
   - ежедневная сводка работы агентов в бот (утро, Алматы): сколько задач, успех/ошибки, расход ИИ, что ждёт одобрения;
   - сигнал о зависших задачах (lease истёк, нет прогресса N минут).
   Номер миграции, если нужна: **108**.

## Часть B. «Мозг» ботов (подход 1)

- **Движок** `lib/telegram/brain/*`: цикл до 6 шагов «модель → инструменты → модель» через новый `chatWithTools` в ИИ-слое (OpenAI tools / tool_calls; провайдеры из A1, с переключением). light для простых, standard для сложных. Бюджеты: персональный дневной бюджет сотрудника + платформа/провайдер.
- **Асинхронность**: вебхук отвечает 200 сразу, обработка в фоне (`waitUntil` из `@vercel/functions`), `sendChatAction typing` каждые ~4 с.
- **Инструменты чтения**: 8 MCP (`lib/mcp/tools.ts`, через `runTool` с principal/scopes роли) + новые: заявки и пользователи, застрявшие на анкете, задачи и эскалации, события платформы, агенты и одобрения. PII только с `users.sensitive`.
- **Действия** (модель лишь предлагает → карточка + `ctx.confirm` → выполнение существующими функциями с проверкой прав и аудитом): одобрить/отклонить заявку; напомнить про анкету (одному/группе); задача/ответственный; заметка клиенту; одобрение действия агента; перезапуск задачи агента; прикрепить файл к клиенту.
- **Бот экспертов**: разбор клиента (GRI, Точка А, динамика), черновик комментария/рекомендаций, пересказ отчёта на проверке; только клиенты в видимости эксперта.
- **Голос**: `getFile` → скачивание → `transcribe` (Alem Speech-to-Text / Kaz STT; иначе модель с аудио-входом через OpenRouter) → текст показывается строкой «🎙 …» и обрабатывается как вопрос.
- **Фото/файлы**: фото → vision-модель; документ → `extractDocumentText` → ответ по содержанию; «прикрепить к клиенту» → загрузка в storage + `finalizeUpload` через подтверждение.
- **Память**: последние ~10 реплик на чат, 24 ч, `/new` — сброс. Миграция **109**.
- **Защита**: данные — недоверенный текст (`UNTRUSTED_DATA_RULES`); только инструменты роли; лимит сообщений на чат; аудит действий; секреты/ключи никогда не уходят в модель.
- Меню и команды остаются.

## Тесты

Подставные fetch/модель: обнаружение и эвристики capability; автомаршрутизация и переключение (включая «явная модель отсутствует»); circuit breaker; уведомления агентов и анти-спам; цикл инструментов, права по ролям, подтверждения, PII-гейт; голос/фото/документ на заглушках; асинхронный вебхук (200 сразу).
