# ТЗ: Ремейк GRI, мини-CRM в GRI Pulse, онбординг-экскурсия «Гри», оповещения

**Дата:** 2026-07-08 · **Статус:** утверждено по Q/A с продакт-оунером (Марина)
**Ветка:** `claude/gri-pulse-crm-improvements-a0017a` (worktree wonderful-knuth-015991)

## 0. Контекст и решения продакт-оунера

Запрос: (1) объяснить `NEXT_PUBLIC_MARKET_APP_URL`; (2) полный ремейк страницы /gri;
(3) туториал — только при первом входе, подробнее, без выхода за границы, советы Гри
с рабочими кнопками при обнаружении проблем; (4) GRI Pulse: ползунки вниз, сверху —
простой и полезный CRM-инструмент (статусы, «кому позвонить», возврат лидов),
НЕ заменяющий AmoCRM/Bitrix24.

Зафиксированные в Q/A решения:

| Вопрос | Решение |
|---|---|
| Страница GRI | Полный ремейк, макет — **вкладки** (hero сверху, ниже: Оценка / Результат / Динамика / AI-аналитик) |
| Туториал | **Гибрид**: welcome от Гри при первом входе → экскурсия-чеклист по страницам, на каждой короткий тур 3–5 шагов; повторно — только вручную из раздела «Обучение» в панели Гри |
| Источник клиентов CRM | **Оба**: своя база в портале + синк из AmoCRM/Bitrix24 |
| Расположение CRM | На **/pulse сверху** + пункт бокового меню «Клиенты», ведущий туда же; полный набор функций: база, воронка, аналитика состояния, рекомендации кому позвонить |
| Поля клиента | Базовый + деньги: имя*, телефон*, статус, следующий контакт, заметки, средний чек/сумма, источник |
| Оповещения | Все каналы: портал, Email, Telegram, Push (PWA), SMS + WhatsApp на телефон из анкеты. SMS — adapter, включается после появления ключей провайдера |
| Порядок фаз | **GRI → CRM → Туториал → внешние каналы/синк** |

`NEXT_PUBLIC_MARKET_APP_URL` — отвечено (не кодовая задача): origin задеплоенного
Mark-analytics SPA для iframe /market ([components/market/MarketAppEmbed.tsx:31]);
прод: задеплоить Mark-analytics → задать env в Vercel-проекте портала + `MARKET_API_URL`
→ ребилд (build-time переменная). См. docs/market-deployment.md.

## 1. Находки разведки, определяющие дизайн

1. **«Туры постоянно» — баг персистенции**: `writeMascotSettings`
   (lib/assistant/mascot/settings-server.ts:136-142) не проверяет число обновлённых
   строк; RLS молча отбрасывает UPDATE profiles.preferences → `toursDone` не
   сохраняется → сервер затирает локальное зеркало → автозапуск при каждом ремоунте.
   Плюс гонка: параллельный `/context` со старыми settings клоббирует свежий toursDone.
2. **Карточка тура выходит за экран**: в MascotCoachmarks.tsx framer-motion `animate`
   перезаписывает `transform: translateY(-100%)` (позиционирование «над таргетом»
   не работает), нет клампа по нижней границе, ширина 330px фиксирована (мобильные).
3. **CRM полуживой**: клиенты «Кому звонить» = live-сделки Bitrix24/AmoCRM + клиенты
   платформы (Choco-демо удалён), но `requireCrmOrg()` всегда отдаёт `orgId=null` →
   все /api/crm дают 403; синк ничего не сохраняет; CallModal/MessageModal — имитация
   с фейковыми телефонами; таблиц клиентов пользователя нет. `findFirst({isActive})`
   без скоупа = межарендная утечка. Имя таблицы `clients` занято мёртвой Prisma-моделью.
4. **Калькулятор GRI не персистится**: сессии/история/сравнение — localStorage;
   «PDF» — .txt; PDF/XLSX в «Финансовом аналитике» не читаются (уходит `[File: имя]`),
   анимация парсинга — setTimeout-театр; динамические инсайты упираются в 429.
   Единственный источник правды — таблица `gri_assessments` (миграция 021).
5. **Уведомления**: внутренняя лента `app_notifications` + Resend + Telegram-хелперы
   и adapter-паттерн эскалаций (internal/email/telegram/whatsapp) уже есть;
   `profiles.preferences.notifications` сохраняется, но при отправке НЕ читается;
   `profiles.telegram_chat_id` нет в миграциях и нет привязки бота; Web Push и SMS
   отсутствуют; телефон анкеты — свободный текст без нормализации.
6. **UX-исследования**: сквозные туры бросают 78% к 3-му шагу; работают чеклист +
   туры 3–5 шагов + ручной перезапуск (launcher ~67% completion). Лёгкие CRM выигрывают
   очередью «кому звонить сегодня», правилом «у каждого клиента есть следующий шаг»,
   сортировкой по дате контакта, индикатором «протухания» и таймлайном касаний.

## 2. Секция A — Ремейк страницы /gri (Фаза 1)

### Макет
Hero-панель (всегда видна): текущий GRI из `gri_assessments` + цель 8.5 + статус-бейдж
+ CTA по контексту (нет диагностики → «Пройти тест»; есть → «Обновить оценку»).
Ниже — вкладки:

1. **Оценка** — калькулятор: 7 слайдеров + радар (recharts, уже есть), выбор ниши/
   размера (бенчмарки), режим планирования, мгновенные микро-инсайты при движении
   ползунков из локального `MICRO_INSIGHTS` (без LLM, без 429); полный тест
   (GRIAssessment, 62 критерия) встраивается сюда же как «Точная диагностика»
   (текущая state-machine сохраняется).
2. **Результат** — итоговый индекс, зоны, TOP-5 ограничений, план 90 дней
   (lib/gri-calculator/top5-action-plan.ts), CTA «Забронировать разбор».
3. **Динамика** — история замеров с сервера (GET /api/v1/gri/assessment?history=1,
   до 20) + сессии калькулятора + линия недельного пульса (gri_pulse_responses);
   сравнение «текущий vs выбранный прошлый» по блокам (дельта-бейджи как в Pulse).
4. **AI-аналитик** — «Стратегия роста» (по кнопке, /api/gri/ai-strategy) +
   «Финансовый аналитик» (загрузка отчёта).

### Функциональные правки (честность)
- **Сессии калькулятора → БД**: новая таблица `gri_calc_sessions` (user_id, scores
  JSONB, gri_index, niche, size, note, created_at; RLS own+staff по шаблону 027).
  API: `app/api/v1/gri/calc-sessions/route.ts` (GET список ≤20 / POST / DELETE).
  «Сохранить сессию», история и «сравнить с прошлым» работают кросс-девайс;
  localStorage остаётся офлайн-фолбэком.
- **Финансовый аналитик читает файлы по-настоящему**: PDF/XLSX/CSV через существующий
  парсер `lib/documents/parse.ts` (OpenRouter); театральные setTimeout-стадии убрать,
  прогресс — реальные этапы (загрузка → извлечение → анализ). Если ключа AI нет —
  честное сообщение «AI недоступен», а не молчаливая эвристика.
- **Экспорт**: «Скачать PDF» — настоящий PDF (переиспользовать PDF-экспорт mini-GRI);
  если объём работ окажется большим — в v1 честно переименовать кнопки в «Скачать отчёт (.txt)».
- **Синхронизация без потери данных**: точные средние секций (без Math.round-скачка
  индекса после первого движения слайдера); «Применить к дашборду» из финансового
  аналитика предлагает сохранить как сессию.
- **Мёртвый legacy**: POST /api/clients/[id]/gri/calculate (Inngest, гарантированно
  падает) — удалить/вернуть 410; мёртвый GriPulsePage.module.css удалить.
- **Мобильная адаптация**: вкладки скроллятся, слайдеры с крупными тач-зонами,
  радар сжимается корректно.

Вне скоупа: объединение dual-engine (lib/gri/logic.ts 0–100 для /ai-scanner и
мини-GRI) — отдельная задача, здесь не трогаем.

## 3. Секция C — GRI Pulse → лёгкий CRM (Фаза 2)

### Компоновка /pulse
Сверху — CRM-блок (см. ниже), внизу — «Пульс недели» (GriPulseWidget) в компактном
виде (сворачиваемая секция; если пульс за неделю не снят — липкая напоминалка-строка
над футером). Нижний существующий блок «Кому звонить сегодня» сохраняет текущий вид
карточек (требование ПО), меняется только его позиция/обвязка. Боковое меню получает
пункт **«Клиенты»** → /pulse#clients (или query-tab).

### Данные (миграция 043, apply-migration.js; префикс `crm_` — имя clients занято)
- `crm_clients`: id UUID, user_id → auth.users, name*, phone (E.164, nullable),
  status ENUM-текст (`new|in_progress|waiting|customer|sleeping|lost`), source,
  avg_check NUMERIC, next_contact_at, last_contact_at, notes, created_at, updated_at.
  Индексы: (user_id, status), (user_id, next_contact_at). RLS: own CRUD + staff-read
  (шаблон 042/027). Только snake_case.
- `crm_interactions` (append-only таймлайн): id, client_id FK CASCADE, user_id,
  kind (`call|message|meeting|note|status_change`), comment, created_at.
- `crm_reminders`: id, client_id FK, user_id, due_at, note,
  status (`open|done|dismissed`), created_at, done_at.
  Закрытие напоминания пишет interaction и предлагает следующий шаг.

### API (`app/api/v1/crm/…`, конверт {ok, data}, zod-валидация)
`clients` CRUD + `clients/[id]/interactions` + `clients/[id]/reminders` +
`clients/import` (CSV/XLSX: маппинг русских заголовков, дедуп по нормализованному
телефону) + `today` (очередь дня, см. ниже).

### UI (все тексты — русские, стиль портала)
1. **Экран «Сегодня»** (первая вкладка CRM): очередь = просроченные напоминания →
   на сегодня → клиенты без следующего шага → «давно не общались» (last_contact_at
   > 30 дней, статус customer/sleeping). Режим «по одному»: карточка → кнопки
   `tel:` / `wa.me/<номер>` (реальный телефон) → форма результата (однострочный
   комментарий + следующий шаг) → interaction + reminder.
2. **База клиентов**: таблица с инлайн-добавлением (имя + телефон, 5 секунд),
   поиск, фильтры по статусу; **воронка-бар** над таблицей — сегменты-статусы
   с количеством и суммой avg_check, клик = фильтр; смена статуса — селект в
   строке (пишет status_change в таймлайн). Индикатор давности контакта:
   зелёный <7д / жёлтый 7–30д / красный >30д. Канбан-вид — не в v1;
   вернёмся к нему по итогам реального использования списка.
3. **Карточка клиента** (drawer): поля + таймлайн касаний + напоминания +
   быстрые действия. «История» в существующем ClientCard оживает этим же drawer.
4. **Аналитика состояния** (компактная строка KPI над вкладками): всего клиентов,
   в риске (red), «выручка под риском» (сумма avg_check красных), обработано
   сегодня. Риск-движок переиспользуется из /api/pulse (детерминированный скоринг)
   поверх crm_clients. Рекомендации «кому позвонить для удержания/реактивации» —
   это и есть очередь «Сегодня» + AI-брифинг (существующий /api/pulse/briefing,
   расширенный данными crm_clients).
5. **CallModal/MessageModal**: реальные телефоны клиента, «Зафиксировать» пишет
   interaction (ложные надписи убрать); MessageModal открывает wa.me / tel: и
   логирует касание.

### Синк AmoCRM/Bitrix24 (Фаза 4)
- Новая таблица `crm_provider_connections` (user_id, provider, credentials, статусы
  синка; RLS own) — замена мёртвой Prisma `crm_integrations`; UI CrmIntegrationTab
  переподключается на неё; скоуп по user_id закрывает межарендную утечку
  `findFirst({isActive})` в /api/pulse и /api/pulse/briefing.
- REST-клиенты lib/crm/bitrix24.ts / amocrm.ts переиспользуются; синк реально
  импортирует контакты+сделки в `crm_clients` (upsert по телефону, source =
  `bitrix24|amocrm`), по кнопке «Синхронизировать».

## 4. Секция B — Онбординг и «Гри» (Фаза 3; баг-фиксы — в Фазе 1)

### Баг-фиксы (Фаза 1, до остального)
1. **Персистенция**: `writeMascotSettings` — `.select()` после UPDATE и проверка,
   что строка вернулась; при 0 строк — ошибка в лог + retry через service role
   недопустим (RLS-политика на profiles уже позволяет self-update — проверить,
   починить причину, не симптом). Клиент: merge `toursDone = union(server, local)`
   при setContext (гонка клоббера), батч-PATCH по завершении тура.
2. **Геометрия карточки**: убрать конфликт transform (позиционировать только через
   top/left с учётом измеренной высоты карточки), клампить в вьюпорт со всех
   сторон, ширина `min(330, vw-24)`; liveSteps пересчитывать при изменении DOM
   (poll/MutationObserver с таймаутом + graceful skip), а не один раз в useMemo.

### Онбординг-экскурсия (Фаза 3)
- **Welcome от Гри** при первом входе (флаг greeted, серверный): 1 модалка —
  «Покажу главное? ~2 минуты» / «Разберусь сам». Отказ ≠ провал: чеклист остаётся
  доступен из панели Гри.
- **Экскурсия-чеклист** «Первые шаги» (владелец): Дашборд → Анкета → GRI →
  Точка А → Точка Б → Pulse+Клиенты → Метрики → Рынок. Пункт = router.push +
  локальный тур страницы (3–5 шагов, прогресс «2/5», где возможно — интерактивные
  шаги «нажми сам»). Для эксперта — свой набор. Позиция чеклиста персистится
  (profiles.preferences.assistant.tourChecklist: {stepIdx, status}), состояние
  тура — в zustand persist-слайсе (переживает ремоунт между layout-группами).
  Ожидание таргетов после навигации — observer/poll, не setTimeout.
- **Каталог туров**: tours.ts дополняется до полного покрытия страниц и функций
  (dashboard, onboarding, gri (по вкладкам), pulse+CRM, point-a/b, metrics,
  market, reports, notifications, settings; owner и client-варианты). Максимум
  5 шагов на тур.
- **Раздел «Обучение» в панели Гри**: список туров текущей страницы + всех разделов,
  перезапуск вручную; кнопка «Пройти экскурсию заново». Автопоказ — никогда после
  dismissal.
- **Empty-states как онбординг**: пустые CRM/Pulse/Point B получают реплику Гри
  с CTA (например «Сначала пройди GRI — построю план»).

### Советы Гри при проблемах (Фаза 3)
Расширить `computeServerHints` (lib/assistant/mascot/server-hints.ts) + каталог
hints.ts новыми типами с кнопками `navigate` (механизм работает):
- `empty_metrics` → /metrics («Пустая метрика искажает расчёты — заполните…»);
- `red_zone` → /gri?tab=result (блоки GRI < 5 или Point A critical);
- `clients_at_risk` → /pulse#clients (есть красные клиенты / просроченные
  напоминания) — требует чтения crm_clients в buildAssistantContext строго
  по user_id сессии (не повторить expert-no-scoping);
- `pulse_missed` → /pulse (пульс недели не снят к четвергу).
Для проблемных советов — отдельный класс cooldown-правил (мягче per-hint 24ч,
но не спам: максимум 1 проблемный совет за визит страницы).

## 5. Секция D — Оповещения (Фаза 2 — внутренние; Фаза 4 — внешние)

- **Движок**: Vercel cron (утро, 09:00 Asia/Almaty) → `app/api/cron/crm-digest`
  (защита CRON_SECRET): по каждому пользователю собрать просроченные/сегодняшние
  напоминания + спящих клиентов → fan-out по каналам **с учётом
  profiles.preferences.notifications** (сейчас декоративны — подключить).
- **Каналы v1 (Фаза 2)**: in-app — `createNotification` в app_notifications
  (категория `crm`, link на /pulse#today), колокольчик уже работает.
- **Каналы v2 (Фаза 4)**: Email-дайджест (Resend, шаблон готов); Telegram —
  миграция `profiles.telegram_chat_id` + привязка: deep-link `t.me/<bot>?start=<код>`
  + webhook `/api/telegram/webhook`, кнопка в Настройках.
- **Каналы v3 (Фаза 4, за env-флагами, adapter-паттерн эскалаций)**:
  WhatsApp Cloud API — только после одобрения шаблонов Meta (вне 24ч окна текст
  отклоняется — зафиксировано в коде); SMS — интерфейс `SmsAdapter` + заглушка,
  включение после ключей провайдера (решение ПО: отложить); Web Push — VAPID +
  таблица подписок + web-push (последним, самый затратный).
- **Телефон анкеты**: нормализация в E.164 при сохранении (s1_contact_phone,
  profiles.phone) + мягкий backfill; company-роут перестаёт спредить сырой body.

## 7. Технические конвенции (обязательны для агентов-исполнителей)

- Миграции: `supabase/migrations/043_*.sql` и далее, идемпотентные, RLS по шаблону
  027/042, только snake_case, `NOTIFY pgrst, 'reload schema'`; применение —
  `node scripts/apply-migration.js <file>` (и вручную на prod!).
- Не использовать Prisma-таблицы clients / notifications / pulse_metrics /
  crm_integrations (мёртвый стек, camelCase-колонки); FK — на auth.users/profiles
  (companies.id — TEXT cuid, прямой FK нельзя).
- API — `app/api/v1/...`, конверт `{ok, data|error}`, zod, rate-limit по образцу
  существующих роутов; клиентские записи — под сессией пользователя (RLS),
  системные — service role.
- UI: русский, тёмная тема, primary #6effc0, Material Symbols, framer-motion,
  существующие компоненты (DeltaBadge, RiskBadge, MiniSparkline, ClientCard…).
- После UPDATE под RLS всегда проверять затронутые строки (урок admin-аудита).
- `npm test && npm run lint` перед каждым коммитом; коммиты по фазам.
