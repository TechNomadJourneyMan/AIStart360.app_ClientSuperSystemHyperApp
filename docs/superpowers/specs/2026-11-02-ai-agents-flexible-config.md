# Гибкая настройка ИИ-агентов — дизайн (без кода)

Дата: 2026-11-02. Продолжение решения PO: Claude — модель по умолчанию, Alem/Qwen (llm.alem.ai) — дешёвый уровень и запасные (миграция 137).

## Сейчас

- Маршрут задаётся только на уровень (`ai_routes`: light / standard / premium) — один на всю платформу. Фича выбирает уровень в коде (`complexity` → `COMPLEXITY_TIER`, lib/ai/complexity.ts).
- `agent_configs` (086) настраивает только агентов рантайма (`tier_override`, `model_override`, бюджеты). Фичи из `AI_FEATURES` (lib/ai/usage.ts: `point_a_analysis`, `omnichannel`, `survey_assistant`, …) без деплоя не перенастроить.
- Ограничить провайдера для чувствительных данных нельзя: любая фича может уйти в OpenRouter как запасной.

## Что настраивает владелец (на «агента» = фичу или агента рантайма)

1. Уровень (tier) — например, блоки Точки А: light → standard.
2. Цепочку моделей и порядок запасных: явный список моделей; режим «только цепочка» или «цепочка, затем маршрут уровня и авто-подбор».
3. Дневной бюджет фичи, $.
4. Разрешённых провайдеров — например, данные клиента только у KZ-провайдера (llm.alem.ai), OpenRouter запрещён.
5. Эскалацию структурного ответа (вкл/выкл, потолок уровня).

## Где хранится

Таблица `ai_agent_profiles` (миграция 138, RLS и доступ как у 094 — только сервер):
`agent_key` PK (`point_a_analysis` или `agent:<key>`), `enabled`, `tier` NULL, `model_chain uuid[]` NULL (ai_models.id, только chat), `fallback_mode` (`chain_then_route` | `chain_only`), `allowed_providers text[]` NULL (= все), `daily_budget_usd` NULL, `escalate_structured` (по умолчанию true), `max_tier` NULL, `updated_by`, `updated_at`. Профили грузятся в тот же снапшот роутера (кэш ≤ 60 с, `invalidateProviderCache()` после записи).

## Как подключается к роутеру

Порядок: **фича → профиль → маршрут уровня → ранжирование по tier_hint → встроенный OpenRouter.**

- `feature` уже обязателен во всех вызовах (`chatWithOpenRouter`, `callLlm`, `chatWithTools`); по нему берётся профиль.
- Уровень = `profile.tier` ?? уровень вызова. Явный `model` из кода остаётся сильнее (vision / аудио / тесты), но проходит фильтр провайдеров.
- `resolveCandidates(…, { profile })`: сначала рабочие модели `model_chain` в заданном порядке; при `chain_then_route` — дальше текущие шаги 1–5; **последним** — фильтр `allowed_providers` по `providerKey` (его не обходит ни один шаг, включая встроенный OpenRouter). Пусто → `NOT_CONFIGURED` «для фичи нет разрешённой модели».
- Бюджет фичи — ещё одна проверка в `budgetCheck` рядом с `providerBudgetRefusal` (расход за сутки из `ai_usage_ledger.source = feature:<label>`), в проде fail-closed.
- structured.ts: эскалация только при `escalate_structured` и не выше `max_tier`.

## Интерфейс: GIGA → «AI-провайдеры» → вкладка «Агенты»

Таблица фич (название из `AI_FEATURES`, расход за 7 дней, «кто отвечает» — та же `resolveCandidates` в режиме просмотра). Редактор: уровень, цепочка (перетаскивание из chat-моделей), режим запасных, провайдеры (флажки), бюджет, эскалация. Каждое изменение пишется в аудит (`recordAdminAction`, required), как для провайдеров. Предупреждение, если фильтр провайдеров не оставил ни одной рабочей модели.

## План миграции

1. 138: пустая таблица — поведение не меняется.
2. Код: профили в снапшоте, `resolveCandidates` с профилем, фильтр провайдеров, бюджет фичи; юнит-тесты на fake-store.
3. API `/api/giga-admin/ai-providers/agents` (GET/PUT, аудит) и вкладка «Агенты».
4. Рекомендуемые профили — только после подтверждения PO (например, `omnichannel`, `survey_assistant`, `doc_extract` → только KZ-провайдер).
5. Перенос `agent_configs.tier_override / model_override` в профили `agent:<key>` (сначала чтение из обоих мест, удаление колонок — отдельной миграцией).
