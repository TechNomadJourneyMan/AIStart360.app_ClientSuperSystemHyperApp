# Точка А · Фаза 3: цели как единый источник. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Цель задаётся по любой метрике каталога: значение, срок (дата) и база (значение и период метрики в момент постановки). Для каждой цели считаются разрыв А→Б, требуемый темп, реалистичность и статус. Единый источник — `metric_targets`. Колонки `companies.target_revenue_*` синхронизируются ради совместимости. `GoalsBar` сохраняет цели в БД. Изменение цели пересчитывает Точку А (блок «Мои цели» в снимке) и Точку Б.

**Spec:** §3.

## Решения
- **Метрика выручки цели:** `biz.finansy.vyruchka_god`. Синхронизация: `period_label '12m'` ↔ `target_revenue_12m_kzt`, `'3y'` ↔ `target_revenue_3y_kzt` — в обе стороны, через маршруты записи (не триггером БД: `companies` пишет много кода).
- **Срок:** явный `deadline`; без него — из `period_label` (`12m` → дата создания + 12 мес., `3y` → + 36 мес., `2026-Q4` → конец квартала, `2026` → конец года).
- **Реалистичность**, обобщение `assessRealism`:
  - денежные и счётные метрики (`₸`, `count`, без единицы) — по требуемому годовому темпу (CAGR): ≤ 20 % реалистично, ≤ 50 % амбициозно, ≤ 100 % агрессивно, иначе нереалистично;
  - процентные и балльные (`%`, «из 10», NPS) — по изменению в пунктах за год: ≤ 5 п. п. реалистично, ≤ 15 амбициозно, ≤ 30 агрессивно, иначе нереалистично;
  - `lower_is_better` — по обратному отношению.
- **Статус** (по базе и прошедшему времени):
  - прогресс = (текущее − база) / (цель − база), время = прошло / весь срок;
  - `achieved` при прогрессе ≥ 1, `on_track` при прогрессе ≥ время − 0.1, `at_risk` при ≥ время − 0.3, иначе `behind`;
  - `no_data` без текущего значения; `overdue`, если срок прошёл, а цель не достигнута.
- **Миграция 112:** `metric_targets` + `deadline date`, `baseline_value`, `baseline_period`, `label`, `updated_by`; бэкфилл из `companies.target_revenue_*`.

## Задачи
1. `lib/goals/evaluate.ts` (чисто): `goalDeadline`, `evaluateGoal`, `realismFor`. Тесты.
2. Миграция 112 + `lib/goals/store.ts`: `loadGoals` (с запасным путём через `companies`), `upsertGoal`, `deleteGoal`, `syncRevenueColumns`.
3. API `GET/POST /api/v1/goals`, `DELETE /api/v1/goals/[id]`: тенант из сессии, запись с правом manage через service role, `TARGET_CHANGED`. Тесты.
4. `PATCH /api/v1/companies/targets` синхронизирует `metric_targets` и отправляет `TARGET_CHANGED`.
5. `GoalsBar`: пресеты привязаны к метрикам, сохранение через API (zustand больше не хранит цели).
6. Снимок Точки А: цели во входах (их изменение — новый снимок) и в `v4.goals` (оценка). Точка Б: `metric_goals` в ответе `diagnostics/point-b` (оценка всех целей).
7. Проверка фазы: тесты, `tsc`, `lint`, ревью; миграция 112 — после подтверждения.
