### 2.7 Метрики: источники, формулы, единый источник (W4, 2026-10-06)

Все 148 метрик реестра (`lib/metrics/registry.ts`) объявляют источники в своей единице и своём смысле (`lib/metrics/descriptions.ts`); вход формулы больше не бывает источником самой метрики.

**Порядок источников метрики** (`lib/metrics/resolver.ts`): ручной ввод → документ → оценка GRI → анкета (текущий мастер) → формула → анкета старой версии (`legacy: true`) → CRM/Prisma → внешние системы. Источник, который не дал числа для этой метрики (свободный текст, диапазон, «8 из 10» для денег, процент для ₸, значение в $, вне диапазона метрики), — промах с причиной и не блокирует следующий.

**Разбор ответа** (`lib/metrics/numbers.ts`): ровно одно число с необязательными словами масштаба (тыс/млн/млрд/k/m), валютой, «%», словом периода («в месяц», «/год») и приблизительностью («около»); диапазон, отношение, несколько чисел или посторонние слова → нет значения. Шкала 0–10 принимает «8 из 10», «8/10», «4 из 5» (→ 8). Поля формы, которые пишут 0 для пустого (`zeroIsEmpty`: цикл сделки, сотрудники, этапы воронки), 0 считают «не заполнено».

**Период** (`lib/metrics/period.ts`): у потоковых метрик объявлен период (`period: 'year' | 'month'`). Значение другого периода пересчитывается (квартал → год ×4, месяц → год ×12, год → месяц ÷12) с записью в provenance (`period: {source, target, factor, basis}`) и пониженной уверенностью (×0,85). Период документа: подпись поля («2025-Q1», «март 2025», «9 месяцев 2025») → `documents.period_year/period_quarter` → имя файла → текст документа («за 1 квартал 2025 года»). Из нескольких документов берётся значение за полный период метрики, затем самый поздний период, затем бо́льшая уверенность, затем новая загрузка.

**Единицы**: проценты хранятся в процентах (доля 0,34 из документа → 34 % с пометкой), NPS и eNPS — индекс −100…100 (не «%»), баллы GRI — «из 10», CAC payback — месяцы, время ответа — минуты, «… дни» — дни. Деньги в другой валюте не превращаются в ₸.

**Формулы** (`lib/metrics/formulas.ts`, 28 формул): CPL = реклама/мес ÷ лиды/мес; CAC = реклама за год ÷ новые клиенты; LTV/CAC; win/loss rate = сделки (отказы) ÷ (сделки + отказы) за один год; средний чек = выручка ÷ сделки за один год; КП → сделка = произведение трёх этапов воронки шага 5; валовая маржа = (выручка − себестоимость) ÷ выручка; EBITDA = выручка − себестоимость − опер. расходы; опер. расходы = маркетинг + аренда + прочие (шаг 9); ROA = чистая прибыль ÷ активы; дебиторка ≈ выручка ÷ 365 × срок оплаты; расходы на рекламу = % бюджета × выручка; ARPU, выручка на продажника (штатное расписание, отдел продаж), производительность, доля экспорта, повторные продажи, частота покупок, LTV из оттока, CAC payback, доли рефералов и клиентов конкурентов. Формула считается только когда все входы одного варианта есть (порядок зависимостей, циклы запрещены); иначе метрика пустая с «нужно: …». Provenance `calculated`: каждый вход, его значение и источник. Базовые входы, которые не являются метриками каталога (чистая прибыль, активы, строки расходов, сделки/отказы по годам), резолвятся теми же адаптерами и не материализуются.

**Документы**: поле документа сопоставляется через словарь синонимов (`lib/documents/synonyms.ts`; у каждого поля источника есть запись — тест), семейства типов документов (`lib/documents/doc-types.ts` `DOC_TYPE_FAMILIES`: `financial_report` и `pl_statement` питают P&L-метрики, `ads_report`/`ga4_export` — маркетинговые, `sales_report`/`client_base` — CRM-метрики; бизнес-план и презентация — никогда). Клиентская база (`client_rows`) даёт число активных клиентов и долю клиентов с 2+ покупками. OCR-поля сохраняют уверенность ≤ 0,7 и в `metrics.provenance.document` — движок OCR, уверенность страницы, страницу и цитату.

**GRI-метрики** (`gri.*`, «Метрики команды (GRI)», «Product Score (GRI)», «Повторяемость процессов», «Предсказуемость») берутся из разделов текущей оценки GRI (`gri_assessments.section_avgs`), а не из сумм ответов анкеты; `metrics.source = 'calculated'`, `provenance.picked.type = 'assessment'`.

**Единый источник значений** (`lib/metrics/company-metrics.ts`): материализация (`lib/metrics/materialize.ts`) держит одну текущую строку на метрику (строки других источников и метрик, которые больше не считаются, удаляются после записи; строки снятых источников — до записи). Каталог (`/api/v1/metrics/catalog`), вкладки KPI и «Цели» страницы Метрик (`components/metrics/NamespaceMetricsTab.tsx` — тот же каталог), дашборд (`/api/v1/metrics`, `GrowthSnapshotHero`, `KeyMetricsHero`), входы движка Точки А (`lib/point-a/resolved-inputs.ts`: маржа, LTV, CAC, LTV/CAC, цикл сделки, доля повторных, доля отказов — из всех источников) и Точка Б (`lib/point-b/metrics.ts`: текущая выручка и рычаги) читают одно и то же правило «текущей строки». Сквозной тест `tests/unit/metrics/golden-surfaces.test.ts`: анкета + P&L CSV + скан через OCR → одинаковые числа на всех поверхностях.
