# 10. Запуск ботов и добавление ключей (инструкция владельца)

Документ для владельца платформы (super_admin). Здесь описано, как включить два Telegram-бота, как добавлять, менять и удалять ключи ИИ-провайдеров, как подключить WhatsApp (часть 3), как подключить Claude Code / Claude Desktop к данным платформы по MCP (часть 4) и откуда продавец берёт ключи маркетплейсов и аналитики (часть 5).

Два бота:

| Бот | Для кого | Что умеет |
|---|---|---|
| **Админ-бот** (`Command_panel_aistart360_bot`) | Сотрудники AIStart360 со staff-ролью | `/status`, `/agents`, `/approvals`, `/users`, `/clients`, `/reports`, `/providers`, `/spend`, `/notifications`, `/mcp`. Права те же, что в GIGA (RBAC). |
| **Бот экспертов** (`aist360notificationbot`) | Эксперты | `/clients`, `/diagnostics`, `/reports`, уведомления, проверка отчётов (появится после волны 2) |

Токены, секреты и ключи **никогда** не пишутся в git, в чат с ИИ и в логи. Где они хранятся:
- токены ботов — только в переменных окружения Vercel;
- ключи ИИ-провайдеров — в базе, в зашифрованном виде (AES-256-GCM, ключ `SECRETS_ENCRYPTION_KEY`);
- в интерфейсе ключ показывается только замаскированным: «••••abcd».

> Токены и ключи, которые вы уже присылали в чат, считайте раскрытыми. После запуска выпустите новые и замените их:
> - токены ботов: `@BotFather` → `/revoke`;
> - ключи Alem Plus: в кабинете Alem;
> - пароль Postgres и ключи Supabase: в настройках Supabase.

## Часть 1. Запуск ботов

### Шаг 1. Сеть окружения Claude Code (только для проверки из этой сессии)
Это нужно, только если ботов будут проверять из облачной сессии Claude. Для работы на Vercel шаг не нужен.

В настройках окружения claude.ai/code → Network → Allowed domains добавьте:
- `api.telegram.org`;
- `llm.alem.ai`;
- домен вашего Supabase.

### Шаг 2. Переменные окружения в Vercel
Vercel → проект `aistart360app-portal` → Settings → Environment Variables. Значения задайте для Production и, если нужно, для Preview.

| Переменная | Значение |
|---|---|
| `TELEGRAM_ADMIN_BOT_TOKEN` | Токен админ-бота из `@BotFather` |
| `TELEGRAM_ADMIN_BOT_USERNAME` | `Command_panel_aistart360_bot` (без @) |
| `TELEGRAM_ADMIN_WEBHOOK_SECRET` | Случайная строка, см. команду ниже |
| `TELEGRAM_EXPERT_BOT_TOKEN` | Токен бота экспертов |
| `TELEGRAM_EXPERT_BOT_USERNAME` | `aist360notificationbot` |
| `TELEGRAM_EXPERT_WEBHOOK_SECRET` | Другая случайная строка |
| `SECRETS_ENCRYPTION_KEY` | 32 байта в hex (64 символа). **Не меняйте после того, как сохранили ключи:** иначе их не удастся расшифровать. |
| `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Из Supabase → Project Settings → API (скорее всего, уже заданы) |

Случайную строку для секрета или ключа шифрования сгенерируйте на своём компьютере:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
Каждую строку генерируйте отдельно: у каждого секрета своё значение.

После сохранения переменных нажмите **Redeploy**: новые переменные применяются только к новому деплою.

### Шаг 3. Миграции базы
Примените по порядку все файлы `supabase/migrations/`, начиная с `083_…` и до последнего. Например, `095` создаёт таблицы ботов, а `099` выдаёт вашему аккаунту роль super_admin. Команда на каждый файл:
```bash
node scripts/apply-migration.js supabase/migrations/083_security_hardening.sql
```
Скрипт берёт `DIRECT_URL` или `DATABASE_URL` из `.env.local` и записывает каждый применённый файл в `schema_migrations`.

До `099` зарегистрируйтесь на `/login` своим email technomadjourneyman@gmail.com. Миграция выдаёт роль только существующему аккаунту.

### Шаг 4. Доступ Telegram к вебхуку
Telegram отправляет обновления POST-запросами на `https://<домен>/api/telegram/admin` и `/api/telegram/expert`.

Preview-деплои Vercel закрыты Deployment Protection, и Telegram получает от Vercel 401. Есть два варианта:
- использовать прод-домен;
- либо выключить защиту: Vercel → Settings → Deployment Protection.

### Шаг 5. Регистрация вебхуков
На своём компьютере, из папки проекта, с теми же переменными, что в Vercel:
```bash
vercel env pull .env.local          # подтянуть переменные (один раз)
npx tsx --env-file=.env.local scripts/telegram/set-webhooks.ts https://<домен>
```
Скрипт делает три вещи:
- ставит вебхук с секретом;
- записывает меню команд на русском;
- показывает `getWebhookInfo`.

Токены и секреты скрипт не печатает.

### Шаг 6. Проверка готовности
```bash
npx tsx --env-file=.env.local scripts/telegram/go-live-check.ts https://<домен>
```
Скрипт проверяет:
- **окружение:** токены, имена, секреты, ключ шифрования;
- **Telegram:** `getMe`, вебхук;
- **домен:** на вебхук должно отвечать само приложение, а не защита Vercel;
- **базу:** все миграции применены, у вас роль super_admin, бот привязан.

У каждой ошибки скрипт пишет, что сделать. «✓ Готово к запуску» означает, что всё на месте.

### Шаг 7. Привязка вашего Telegram
1. Войдите на `/login` своим аккаунтом и пройдите 2FA. Откроется GIGA (`/admin-giga-panel`).
2. GIGA → **«Уведомления»** (`/admin-giga-panel/notifications`) → **«Привязать Telegram»**.
3. Откроется админ-бот. Нажмите **Start**, и аккаунт привяжется. Ссылка одноразовая и действует 15 минут.
4. Отправьте боту `/status`: должна прийти сводка платформы. `/menu` открывает все разделы.

Эксперты привязывают свой Telegram сами: кабинет эксперта `/expert/profile` → «Привязать Telegram». Ссылка ведёт в бот экспертов.

Сотрудники привязываются так же, как вы, через «Уведомления» в GIGA. Бот перепроверяет роль при каждом сообщении: если роль отозвать, бот перестанет отвечать этому человеку.

### Проверка отчётов в боте экспертов

После каждой ИИ-диагностики агент «Отчёт» собирает новую версию отчёта со статусом «на проверке эксперта» — клиент её не видит.

1. Эксперт с привязанным Telegram (кабинет эксперта → «Мой профиль» → «Привязать Telegram») получает в боте экспертов PDF «Версия N · дата» с пометкой «На проверке эксперта» и две кнопки.
2. **«✅ Подтвердить и опубликовать»** — отчёт сразу публикуется клиенту, клиент получает уведомление со ссылкой именно на эту версию.
3. **«✏️ Нужны правки»** — бот просит комментарий одним сообщением (от 3 символов; `/cancel` — выйти). Агент пересобирает отчёт; если данные не изменились, команда получает уведомление поправить данные или выводы. Пересборок по правкам — не больше 3 на одну диагностику (настройка `review_reruns_max` агента «Отчёт»).
4. Список ожидающих версий — кнопка «📝 На проверке» в разделе «📄 Отчёты» или команда `/review`.

Если в платформе включена «Обязательная 2FA для персонала», решение из бота принимается только у эксперта с настроенной двухфакторной защитой. То же самое можно сделать в кабинете эксперта (`/expert/reports`, блок «На проверке»), в GIGA → «Отчёты» и у SuperExpert → «Отчёты на проверке». Копия PDF уходит экспертам письмом, если задан `RESEND_API_KEY`. Нужна миграция `103_report_review.sql`.

Не проверено вживую: отправка файла (`sendDocument`) и письма с вложением реальным Telegram/Resend — покрыто тестами на записывающем `fetch` и заглушке Resend.

## Часть 2. Ключи ИИ-провайдеров

Два провайдера уже созданы миграцией `094`, но без ключей:
- **OpenRouter** — `https://openrouter.ai/api/v1`;
- **Alem Plus** — `https://llm.alem.ai/v1`, с моделью чата `alemllm`.

Пока ключа нет, работает встроенный вариант из env (`OPENROUTER_API_KEY`), если он задан.

### В GIGA (удобнее всего)
GIGA → **«Провайдеры и ключи»** (`/admin-giga-panel/ai-providers`). Изменения требуют права `settings.manage`, оно есть у super_admin.

1. **Добавить ключ.** Карточка провайдера (например, Alem Plus) → «Ключи API» → «Добавить ключ». Если кнопка неактивна, на сервере не задан `SECRETS_ENCRYPTION_KEY`.
   - Название — например, «Основной».
   - Ключ — вставьте его в поле. После сохранения ключ шифруется, и виден только хвост «••••abcd».
2. **Проверить.** Кнопка «Проверить» делает минимальный реальный запрос с этим ключом и сохраняет результат («Ключ работает» или текст ошибки). Один такой запрос — это чат на 1 токен, один эмбеддинг или список моделей.
3. **Заменить** («Заменить секрет ключа») или **выключить** / **удалить**. Старое значение заменяется, история пишется в аудит.
4. **Модели.** «Добавить модель» → ID модели у провайдера и возможность модели:
   - «Чат»;
   - «Эмбеддинги»;
   - «Rerank»;
   - «OCR».

   Для Alem Plus пропишите модели под ваши ключи: эмбеддер, reranker и DeepSeek OCR. Точные ID моделей возьмите в документации или кабинете Alem.
5. **Цены.** Цена входа и выхода, USD за 1M токенов. По ним считается расход, если провайдер сам не сообщает стоимость.
6. **Маршруты.** Раздел «Маршрутизация» назначает модель на каждую возможность:
   - для «Чат» — отдельно на уровни light / standard / premium;
   - для «Эмбеддинги», «Rerank» и «OCR» — одну модель.

   Пустой маршрут означает встроенный вариант из env.
7. **OCR через Alem.** Нужно три действия:
   - в карточке провайдера поставьте «Режим OCR» = `chat_vision`;
   - добавьте модель OCR;
   - назначьте её в маршруте «OCR».

   Без этого сканы распознаёт встроенный tesseract (rus/eng/kaz). Если удалённый OCR ошибается, страница уходит в tesseract, и данные не теряются.
8. **Бюджеты.** «Дневные бюджеты ИИ, USD»: лимит платформы в сутки и лимит на одну компанию в сутки. У каждого провайдера есть ещё свой дневной бюджет. Когда лимит исчерпан, вызовы останавливаются и не превышают его. Расход по дням, провайдерам и функциям смотрите там же.
9. **Свой провайдер.** «Добавить провайдера»:
   - название;
   - идентификатор (латиница);
   - базовый адрес `https://…/v1`;
   - тип: «OpenAI-совместимый» или «OpenRouter»;
   - пути chat / embeddings / rerank;
   - несекретные заголовки;
   - заметка о приватности.

   Ключ в заголовки не вписывайте: для него есть раздел «Ключи».

### В админ-боте
`/providers` открывает список провайдеров. Выберите провайдера, чтобы открыть карточку, и там:
- «➕ Ключ» — бот попросит прислать ключ сообщением;
- «🔄 Заменить ключ», «✅ Проверить», «⏸ Выключить», «🗑 Удалить»;
- «➕ Модель», «🧭 Маршруты моделей», «➕ Добавить провайдера».

Как бот обращается с присланным ключом:
- Сначала **удаляет ваше сообщение с ключом** из чата.
- Затем шифрует ключ и отвечает только маской «••••abcd».
- Если Telegram не дал удалить сообщение, бот попросит удалить его вручную.

`/spend` показывает расход за сегодня и лимиты.

Опасные действия бот выполняет только после кнопки подтверждения: удаление, смена маршрута. Кнопки изменений видят только роли с правом `settings.manage`.

## Часть 3. WhatsApp

WhatsApp — второй канал уведомлений рядом с Telegram (решение владельца: «Оба»):
- **основной** — официальный WhatsApp Cloud API (Meta): сотрудникам, экспертам и клиентам, только одобренными шаблонами;
- **запасной** — существующий мост WhatsApp Web (`docs/WHATSAPP-WEB-BRIDGE.md`): только для сотрудников и только если включить `WHATSAPP_WEB_BRIDGE_FALLBACK=1`. Клиентам и экспертам мост не используется.

Пока Cloud API не подключён, блоки «WhatsApp» в интерфейсе показывают «не подключён», ничего не отправляется. Отправки и статусы Meta проверены только тестами с подставным ответом — **не проверено вживую**; первая живая проверка — шаг 8.

### Шаг 1. Бизнес-аккаунт и приложение Meta
1. В Meta Business Suite (business.facebook.com) — бизнес-портфолио компании. Подтверждение компании (Business Verification) снимает стартовые лимиты на число получателей — пройдите его, когда будете готовы.
2. developers.facebook.com → My Apps → **Create app** → тип **Business** → привяжите к бизнес-портфолио.
3. В приложении добавьте продукт **WhatsApp**. Meta создаст аккаунт WhatsApp Business (WABA).

### Шаг 2. Номер отправителя → `WHATSAPP_PHONE_NUMBER_ID`
WhatsApp → **API Setup** → Add phone number: номер компании (на нём не должен быть активен обычный WhatsApp — иначе его сначала переносят), подтверждение кодом по SMS или звонку. Скопируйте **Phone number ID** (это не сам номер) — это `WHATSAPP_PHONE_NUMBER_ID`.
В WhatsApp Manager добавьте способ оплаты: сообщения-шаблоны, которые начинает бизнес, платные.

### Шаг 3. Постоянный токен → `WHATSAPP_TOKEN`
Временный токен со страницы API Setup живёт сутки — для продакшена нужен токен системного пользователя:
1. Business Settings → Users → **System users** → Add (роль Admin).
2. **Assign assets**: ваше приложение и аккаунт WhatsApp — полный доступ.
3. **Generate new token** → приложение → разрешения `whatsapp_business_messaging` и `whatsapp_business_management` → срок «Never».
Токен показывается один раз: сразу положите его в Vercel (`WHATSAPP_TOKEN`), в чат и в git не пишите.

### Шаг 4. Секрет приложения → `META_APP_SECRET`
Приложение → App settings → Basic → **App secret** → Show. Этим секретом проверяется подпись `X-Hub-Signature-256` каждого вебхука; без него вебхук отвечает 503 и статусы доставки не принимаются.

### Шаг 5. Вебхук статусов
1. Придумайте `META_WEBHOOK_VERIFY_TOKEN` — случайная строка (команда генерации — в части 1, шаг 2).
2. Сначала задайте переменные в Vercel и сделайте Redeploy (шаг 7), затем: приложение → WhatsApp → **Configuration** → Webhook → Edit:
   - Callback URL: `https://<домен-продакшена>/api/webhooks/meta`;
   - Verify token: значение `META_WEBHOOK_VERIFY_TOKEN`;
   - **Verify and save**, затем в Webhook fields подпишитесь на `messages` (через него приходят статусы `sent`, `delivered`, `read`, `failed`).
3. Deployment Protection в Vercel не должна закрывать `/api/webhooks/meta` (как и вебхуки Telegram, часть 1, шаг 4).
4. Переведите приложение в режим **Live** (App Mode), иначе продакшен-вебхуки не приходят.

### Шаг 6. Шаблоны сообщений
WhatsApp Manager → **Message templates** → Create template. Создайте пять шаблонов ровно как в `docs/platform/06-integrations.md`, раздел 7: `staff_alert`, `expert_notification`, `report_review`, `digest` (категория Utility) и `phone_verification` (Authentication, Copy code, срок кода 10 минут). Язык — Russian (`ru`). В URL кнопок укажите адрес продакшена: `https://<домен>/{{1}}`.
Дождитесь статуса **Approved**. Шаблон с другим текстом или числом переменных Meta отклонит при отправке.

### Шаг 7. Переменные в Vercel и миграция
| Переменная | Значение |
|---|---|
| `WHATSAPP_TOKEN` | токен системного пользователя (шаг 3) |
| `WHATSAPP_PHONE_NUMBER_ID` | Phone number ID (шаг 2) |
| `META_APP_SECRET` | App secret (шаг 4) |
| `META_WEBHOOK_VERIFY_TOKEN` | случайная строка (шаг 5) |
| `WHATSAPP_TEMPLATE_LANG` | `ru` (код языка одобренных шаблонов) |
| `WHATSAPP_VERIFY_SECRET` | необязательно: случайная строка ≥ 32 символов для кодов подтверждения (иначе используется `AUTH_SECRET`) |
| `NOTIFY_WHATSAPP_MIN_LEVEL` | необязательно: порог для сотрудников, по умолчанию `WARNING` |
| `WHATSAPP_WEB_BRIDGE_FALLBACK` | `1` — только если работает мост WhatsApp Web в режиме `WHATSAPP_WEB_DELIVERY_MODE=direct` и нужен запасной канал для сотрудников |
| `WHATSAPP_EXPERTS_TO` | необязательно: номера команды в E.164 через запятую, кто согласился получать обращения к эксперту |

Версия Graph API задана в коде одной константой (`lib/omnichannel/meta-client.ts`, `DEFAULT_META_GRAPH_API_VERSION`); `META_GRAPH_API_VERSION` в env её переопределяет.
Redeploy, затем примените миграцию: `node scripts/apply-migration.js supabase/migrations/104_whatsapp_channel.sql`.

### Шаг 8. Привязка номеров и первая проверка
- Сотрудник: GIGA → «Уведомления» → карточка **«Мой WhatsApp»**.
- Эксперт: кабинет эксперта → «Профиль» → блок **WhatsApp**.
- Клиент: Настройки → Уведомления → блок **WhatsApp** (номер подставляется из профиля).

Человек вводит номер, ставит галочку согласия и нажимает «Получить код» — в WhatsApp приходит 6-значный код (шаблон `phone_verification`, действует 10 минут; не больше 3 кодов за 10 минут на человека и 5 в сутки на номер). После ввода кода номер подтверждён и уведомления включены. Выключить можно тем же переключателем, удалить номер — кнопкой «Удалить номер».
Первая живая проверка: привяжите свой номер в GIGA. Если код не пришёл — в таблице `whatsapp_outbox` у строки будет `last_error` с кодом ошибки Meta (номер телефона в ошибках скрыт).

## Часть 4. Подключение MCP (Claude Code / Claude Desktop)

MCP-сервер платформы отдаёт данные **только на чтение**: поиск клиентов, карточка клиента и компании, Точка А, диагностики, метрики, опубликованные отчёты, задачи ИИ-агентов и расходы на ИИ. Доступ — по правам вашей роли, проверяется при каждом запросе (подробности и таблица прав — `06-integrations.md`, §3.5). Подключаться могут сотрудники со staff-ролью и эксперты.

Адрес сервера: `https://<домен>/api/mcp` (для продакшена — `https://portal.aistart360.app/api/mcp`). Перед первым подключением на деплое должна быть применена миграция: `node scripts/apply-migration.js supabase/migrations/101_mcp_server.sql`.

Команды ниже сверены с документацией Claude Code (https://code.claude.com/docs/en/mcp, раздел «Option 1: Add a remote HTTP server» и «Authenticate with remote MCP servers»).

### Вариант А. Вход через браузер (OAuth, рекомендуется)
Токен копировать не нужно, он обновляется сам.

1. Добавьте сервер (без заголовка):
   ```bash
   claude mcp add --transport http aistart360 https://<домен>/api/mcp
   ```
2. В Claude Code выполните `/mcp`, выберите сервер `aistart360` → **Authenticate** (или из терминала: `claude mcp login aistart360`).
3. Откроется страница AIStart360: войдите своим аккаунтом, пройдите 2FA (если включена или обязательна для персонала) и нажмите **«Разрешить доступ»**. На странице видно, какие права получит приложение; права, которых нет у вашей роли, не выдаются.
4. Проверка: `claude mcp get aistart360` — статус `connected`.

Сессия длится до 30 дней без входа (токен доступа — 1 час, продлевается автоматически). Отключить: GIGA → «MCP-доступ» → «Подключённые приложения» → **«Отключить»**, или в Claude Code `/mcp` → «Clear authentication».

### Вариант Б. Личный токен (заголовок Authorization)
1. Создайте токен:
   - GIGA → раздел «Безопасность» → **«MCP-доступ»** → **«Новый токен»**: название, права (галочки — только права вашей роли; контакты клиентов по умолчанию не отмечены), срок 7 / 30 / 90 / 365 дней;
   - эксперт — в кабинете эксперта по адресу `/expert/mcp`;
   - или админ-бот: `/mcp` → **«➕ Новый токен»** → название → отметьте права → выберите срок. Бот пришлёт токен **одним сообщением** с кнопкой **«🗑 Удалить это сообщение»** — скопируйте токен и удалите сообщение.
2. Токен показывается один раз (в базе хранится только его хэш). Скопируйте готовую команду со страницы или выполните:
   ```bash
   claude mcp add --transport http aistart360 https://<домен>/api/mcp --header "Authorization: Bearer <токен>"
   ```
3. Проверка: `/mcp` в Claude Code — сервер `connected`. Если токен неверный или отозван, статус будет `failed` с кодом 401.

Отзыв токена: GIGA → «MCP-доступ» → **«Отозвать»** или админ-бот `/mcp` → «🗑 Отозвать». Токен перестаёт работать сразу. Если у сотрудника отобрали роль или заблокировали аккаунт, его токены и OAuth-подключения перестают работать без отзыва.

### Claude Desktop и claude.ai
Customize → Connectors → **«+ Add» → «Add custom connector»** → название и адрес `https://<домен>/api/mcp`. В блоке **OAuth client** выберите **«Register automatically»** (сервер поддерживает динамическую регистрацию клиента; вариант «Use Claude’s published identity» — Client ID Metadata Documents — пока не поддерживается). Для личного токена вместо OAuth используйте **Request headers**: `Authorization: Bearer <токен>`.
Подключение к коннекторам идёт из облака Anthropic, поэтому домен должен быть доступен из интернета (на preview-деплоях выключите Deployment Protection для `/api/mcp`, `/api/oauth/*`, `/.well-known/oauth-*` и `/oauth/consent/*`).

### Безопасность
- Не пересылайте токен в чатах и не коммитьте его; `.mcp.json` с токеном не кладите в git (используйте `--scope local` или переменную окружения `${VAR}`).
- Каждый вызов инструмента записывается в журнал `mcp_audit` (кто, какой инструмент, без персональных данных в аргументах).
- Лимит: 120 запросов в минуту на токен.

## Часть 5. Подключение маркетплейсов и аналитики

Клиент подключает свои кабинеты сам: **Настройки → Интеграции → «Магазин, маркетплейсы и аналитика»** (может владелец или администратор компании). Сотрудник с правом «Данные компании клиента» (admin, crm_manager, super_expert) может подключить за клиента: **GIGA → «Интеграции» → «Подключить для клиента»** — действие пишется в журнал аудита (без ключа).

Перед первым подключением на деплое должны быть:
1. миграция `node scripts/apply-migration.js supabase/migrations/105_integration_connections.sql`;
2. `SECRETS_ENCRYPTION_KEY` в Vercel (без него подключение по ключу отвечает 503 — ключи открытым текстом не хранятся);
3. работающий крон агентов (`/api/cron/agents` или Inngest `agents-maintenance`) — агент `integration_sync` запускается каждые 15 минут.

Ключ проверяется запросом к сервису **до** сохранения: неработающий ключ не сохраняется. Ключ хранится зашифрованным, в интерфейсе не показывается. «Отключить» удаляет ключ сразу. Все живые подключения пока **не проверены на реальном кабинете продавца** — первую синхронизацию сверьте с кабинетом.

| Сервис | Где продавец берёт ключ | Что вводить |
|---|---|---|
| **МойСклад** | МойСклад → профиль (правый верхний угол) → «Токены» → «Создать токен». Удобнее завести отдельного сотрудника «Интеграция AIStart360» с правами на просмотр показателей и отчётов («Показатели», «Прибыльность», «Остатки»). | Токен доступа |
| **Kaspi Магазин** | Только руководитель компании: веб-кабинет продавца Kaspi (вход по номеру Kaspi Pay) → **Настройки → Токен API → «Сформировать»** (guide.kaspi.kz, вопрос q3196). Токен не меняется; он даёт доступ к заказам и товарам — передавайте только через форму. | Токен API |
| **Wildberries** | Портал продавца WB → Профиль → Настройки → **«Доступ к API»** → создать токен, категория **«Статистика»**, режим «Только чтение». Базовый токен ограничен одним запросом в 2–3 часа — история будет загружаться долго; персональный / сервисный токен — 1 запрос в минуту. | Токен |
| **Google Analytics 4** | 1) Google Cloud Console → проект → включить **Google Analytics Data API**; 2) IAM → **Сервисные аккаунты** → создать → «Ключи» → **JSON**; 3) GA4 → Администратор → **Управление доступом к ресурсу** → добавить e-mail сервисного аккаунта с ролью **«Читатель»**; 4) GA4 → Администратор → Настройки ресурса → **«Идентификатор ресурса»** (цифры). Вход через Google (OAuth) не настроен — у платформы нет OAuth-клиента Google. | ID ресурса + содержимое JSON-файла ключа |
| **Яндекс Метрика** | oauth.yandex.ru → «Создать приложение» → доступ «Яндекс Метрика: получение статистики, чтение параметров своих и доверенных счётчиков» → скопировать ClientID → открыть `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` под логином, у которого есть доступ к счётчику → скопировать токен (инструкция Метрики «Получение OAuth-токена»). Номер счётчика — в списке счётчиков Метрики. | Номер счётчика + OAuth-токен |
| **Shopify** | Только уже существующий custom app, созданный в админке: Settings → Apps and sales channels → Develop apps → приложение с доступом `read_orders` → API credentials → Admin API access token. Новые такие приложения Shopify создавать не даёт — для новых магазинов нужно OAuth-приложение платформы (BLOCKED, `06-integrations.md` §8.1). | Домен `*.myshopify.com` + токен |
| Ozon, InSales, Tilda, 1С-Битрикс, Meta Ads, Яндекс Директ, Google Ads | Живого подключения нет (причины — `06-integrations.md` §8.1, BLOCKED). Что происходит после подключения: агент `integration_sync` за несколько запусков загружает 35 дней истории, затем обновляет последние 3 дня раз в 2–6 часов. Данные попадают в кабинет e-commerce (блок «Подключения», маркетплейсы, каталог, трафик) и в метрики (посещения сайта, средний чек онлайн, SKU, доля возвратов) с пометкой «из подключения» и периодом.

| Симптом | Что сделать |
|---|---|
| «Ключ не принят (нужно переподключить)» / статус «Нужен новый ключ» | Ключ отозван или неверный: выпустите новый и нажмите «Переподключить». Персонал получает уведомление «Интеграция недоступна». |
| «Превышен лимит запросов» | Ничего: следующая синхронизация будет позже автоматически. Для WB — используйте не базовый токен. |
| «Запрос отклонён (проверьте права ключа и настройки)» | У сотрудника МоегоСклада нет прав на показатели / отчёты; у токена WB не та категория; у сервисного аккаунта нет роли «Читатель» в GA4. |
| «Хранилище ключей не настроено» | Нет `SECRETS_ENCRYPTION_KEY` на деплое. |
| Данные «загружаются» долго | Нормально для WB (один день за запуск) и Kaspi с большим числом заказов; блоки покажут полные 30 дней, когда история заполнится. |

## Если что-то не работает

| Симптом | Причина и что сделать |
|---|---|
| Бот молчит | Запустите `go-live-check.ts`. Чаще всего вебхук не установлен (шаг 5) или его блокирует Deployment Protection (шаг 4). |
| `getWebhookInfo`: «Wrong response from the webhook: 401» | Секрет в Vercel не совпадает с тем, с которым ставили вебхук: снова запустите `set-webhooks.ts`. Если 401 от Vercel — выключите Deployment Protection. |
| Вебхук отвечает 503 | На деплое нет токена или секрета бота: задайте переменные и сделайте Redeploy. |
| «Хранение ключей недоступно: не задан SECRETS_ENCRYPTION_KEY» | Задайте ключ в Vercel и сделайте Redeploy. |
| Ключ «не удаётся расшифровать» | `SECRETS_ENCRYPTION_KEY` поменяли: верните прежнее значение или заново введите ключи провайдеров. |
| Бот отвечает «нет доступа» | У аккаунта нет staff-роли, или Telegram привязан к другому профилю. Привяжите заново в «Уведомлениях». |
| WhatsApp: «не подключён на платформе» | Не заданы `WHATSAPP_TOKEN` и `WHATSAPP_PHONE_NUMBER_ID` (часть 3, шаг 7) или не сделан Redeploy. |
| WhatsApp: код не приходит, в `whatsapp_outbox.last_error` код 132001 / 132000 | Шаблон не одобрен, назван иначе или отличается числом переменных — сверьте с `06-integrations.md`, раздел 7. |
| WhatsApp: статус `delivery_unknown` | Meta не ответила вовремя: сообщение могло уйти. Автоматически не повторяется, чтобы не прислать дважды. |
| WhatsApp: статусы доставки не меняются | Вебхук не подписан на `messages`, неверный `META_APP_SECRET` (ответ 401) или приложение не в режиме Live (часть 3, шаг 5). |
| MCP: `failed`, 401 | Токен неверный, истёк или отозван, либо у владельца больше нет staff-роли / экспертного доступа. Создайте новый токен или пройдите OAuth заново. |
| MCP: 403 при вызове инструмента | У токена нет нужного права (пересоздайте токен с ним) или ваша роль его больше не даёт. |
| MCP: «Неизвестное приложение» / «Неверный адрес возврата» на странице входа | Регистрация клиента устарела: удалите сервер (`claude mcp remove aistart360`) и добавьте снова. |
| MCP: 503 «Журнал аудита недоступен» | База недоступна или не применена миграция 101. |
