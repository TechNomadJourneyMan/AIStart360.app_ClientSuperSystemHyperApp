# 10. Запуск ботов и добавление ключей (инструкция владельца)

Документ для владельца платформы (super_admin). Здесь описано, как включить два Telegram-бота и как добавлять, менять и удалять ключи ИИ-провайдеров.

Два бота:

| Бот | Для кого | Что умеет |
|---|---|---|
| **Админ-бот** (`Command_panel_aistart360_bot`) | Сотрудники AIStart360 со staff-ролью | `/status`, `/agents`, `/approvals`, `/users`, `/clients`, `/reports`, `/providers`, `/spend`, `/notifications`. Права те же, что в GIGA (RBAC). |
| **Бот экспертов** (`aist360notificationbot`) | Эксперты | `/clients`, `/diagnostics`, `/reports`, уведомления, проверка отчётов (появится после волны 2) |

Токены, секреты и ключи **никогда** не пишутся в git, в чат с ИИ и в логи. Где они хранятся:
- токены ботов — только в переменных окружения Vercel;
- ключи ИИ-провайдеров — в базе, в зашифрованном виде (AES-256-GCM, ключ `SECRETS_ENCRYPTION_KEY`);
- в интерфейсе ключ показывается только замаскированным: «••••abcd».

> Токены и ключи, которые вы уже присылали в чат, считайте раскрытыми. После запуска выпустите новые и замените их:
> - токены ботов: `@BotFather` → `/revoke`;
> - ключи Alem Plus: в кабинете Alem;
> - пароль Postgres и ключи Supabase: в настройках Supabase.

## Часть 1. Запуск ботов

### Шаг 1. Сеть окружения Claude Code (только для проверки из этой сессии)
Это нужно, только если ботов будут проверять из облачной сессии Claude. Для работы на Vercel шаг не нужен.

В настройках окружения claude.ai/code → Network → Allowed domains добавьте:
- `api.telegram.org`;
- `llm.alem.ai`;
- домен вашего Supabase.

### Шаг 2. Переменные окружения в Vercel
Vercel → проект `aistart360app-portal` → Settings → Environment Variables. Значения задайте для Production и, если нужно, для Preview.

| Переменная | Значение |
|---|---|
| `TELEGRAM_ADMIN_BOT_TOKEN` | Токен админ-бота из `@BotFather` |
| `TELEGRAM_ADMIN_BOT_USERNAME` | `Command_panel_aistart360_bot` (без @) |
| `TELEGRAM_ADMIN_WEBHOOK_SECRET` | Случайная строка, см. команду ниже |
| `TELEGRAM_EXPERT_BOT_TOKEN` | Токен бота экспертов |
| `TELEGRAM_EXPERT_BOT_USERNAME` | `aist360notificationbot` |
| `TELEGRAM_EXPERT_WEBHOOK_SECRET` | Другая случайная строка |
| `SECRETS_ENCRYPTION_KEY` | 32 байта в hex (64 символа). **Не меняйте после того, как сохранили ключи:** иначе их не удастся расшифровать. |
| `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Из Supabase → Project Settings → API (скорее всего, уже заданы) |

Случайную строку для секрета или ключа шифрования сгенерируйте на своём компьютере:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
Каждую строку генерируйте отдельно: у каждого секрета своё значение.

После сохранения переменных нажмите **Redeploy**: новые переменные применяются только к новому деплою.

### Шаг 3. Миграции базы
Примените по порядку все файлы `supabase/migrations/`, начиная с `083_…` и до последнего. Например, `095` создаёт таблицы ботов, а `099` выдаёт вашему аккаунту роль super_admin. Команда на каждый файл:
```bash
node scripts/apply-migration.js supabase/migrations/083_security_hardening.sql
```
Скрипт берёт `DIRECT_URL` или `DATABASE_URL` из `.env.local` и записывает каждый применённый файл в `schema_migrations`.

До `099` зарегистрируйтесь на `/login` своим email technomadjourneyman@gmail.com. Миграция выдаёт роль только существующему аккаунту.

### Шаг 4. Доступ Telegram к вебхуку
Telegram отправляет обновления POST-запросами на `https://<домен>/api/telegram/admin` и `/api/telegram/expert`.

Preview-деплои Vercel закрыты Deployment Protection, и Telegram получает от Vercel 401. Есть два варианта:
- использовать прод-домен;
- либо выключить защиту: Vercel → Settings → Deployment Protection.

### Шаг 5. Регистрация вебхуков
На своём компьютере, из папки проекта, с теми же переменными, что в Vercel:
```bash
vercel env pull .env.local          # подтянуть переменные (один раз)
npx tsx --env-file=.env.local scripts/telegram/set-webhooks.ts https://<домен>
```
Скрипт делает три вещи:
- ставит вебхук с секретом;
- записывает меню команд на русском;
- показывает `getWebhookInfo`.

Токены и секреты скрипт не печатает.

### Шаг 6. Проверка готовности
```bash
npx tsx --env-file=.env.local scripts/telegram/go-live-check.ts https://<домен>
```
Скрипт проверяет:
- **окружение:** токены, имена, секреты, ключ шифрования;
- **Telegram:** `getMe`, вебхук;
- **домен:** на вебхук должно отвечать само приложение, а не защита Vercel;
- **базу:** все миграции применены, у вас роль super_admin, бот привязан.

У каждой ошибки скрипт пишет, что сделать. «✓ Готово к запуску» означает, что всё на месте.

### Шаг 7. Привязка вашего Telegram
1. Войдите на `/login` своим аккаунтом и пройдите 2FA. Откроется GIGA (`/admin-giga-panel`).
2. GIGA → **«Уведомления»** (`/admin-giga-panel/notifications`) → **«Привязать Telegram»**.
3. Откроется админ-бот. Нажмите **Start**, и аккаунт привяжется. Ссылка одноразовая и действует 15 минут.
4. Отправьте боту `/status`: должна прийти сводка платформы. `/menu` открывает все разделы.

Эксперты привязывают свой Telegram сами: кабинет эксперта `/expert/profile` → «Привязать Telegram». Ссылка ведёт в бот экспертов.

Сотрудники привязываются так же, как вы, через «Уведомления» в GIGA. Бот перепроверяет роль при каждом сообщении: если роль отозвать, бот перестанет отвечать этому человеку.

## Часть 2. Ключи ИИ-провайдеров

Два провайдера уже созданы миграцией `094`, но без ключей:
- **OpenRouter** — `https://openrouter.ai/api/v1`;
- **Alem Plus** — `https://llm.alem.ai/v1`, с моделью чата `alemllm`.

Пока ключа нет, работает встроенный вариант из env (`OPENROUTER_API_KEY`), если он задан.

### В GIGA (удобнее всего)
GIGA → **«Провайдеры и ключи»** (`/admin-giga-panel/ai-providers`). Изменения требуют права `settings.manage`, оно есть у super_admin.

1. **Добавить ключ.** Карточка провайдера (например, Alem Plus) → «Ключи API» → «Добавить ключ». Если кнопка неактивна, на сервере не задан `SECRETS_ENCRYPTION_KEY`.
   - Название — например, «Основной».
   - Ключ — вставьте его в поле. После сохранения ключ шифруется, и виден только хвост «••••abcd».
2. **Проверить.** Кнопка «Проверить» делает минимальный реальный запрос с этим ключом и сохраняет результат («Ключ работает» или текст ошибки). Один такой запрос — это чат на 1 токен, один эмбеддинг или список моделей.
3. **Заменить** («Заменить секрет ключа») или **выключить** / **удалить**. Старое значение заменяется, история пишется в аудит.
4. **Модели.** «Добавить модель» → ID модели у провайдера и возможность модели:
   - «Чат»;
   - «Эмбеддинги»;
   - «Rerank»;
   - «OCR».

   Для Alem Plus пропишите модели под ваши ключи: эмбеддер, reranker и DeepSeek OCR. Точные ID моделей возьмите в документации или кабинете Alem.
5. **Цены.** Цена входа и выхода, USD за 1M токенов. По ним считается расход, если провайдер сам не сообщает стоимость.
6. **Маршруты.** Раздел «Маршрутизация» назначает модель на каждую возможность:
   - для «Чат» — отдельно на уровни light / standard / premium;
   - для «Эмбеддинги», «Rerank» и «OCR» — одну модель.

   Пустой маршрут означает встроенный вариант из env.
7. **OCR через Alem.** Нужно три действия:
   - в карточке провайдера поставьте «Режим OCR» = `chat_vision`;
   - добавьте модель OCR;
   - назначьте её в маршруте «OCR».

   Без этого сканы распознаёт встроенный tesseract (rus/eng/kaz). Если удалённый OCR ошибается, страница уходит в tesseract, и данные не теряются.
8. **Бюджеты.** «Дневные бюджеты ИИ, USD»: лимит платформы в сутки и лимит на одну компанию в сутки. У каждого провайдера есть ещё свой дневной бюджет. Когда лимит исчерпан, вызовы останавливаются и не превышают его. Расход по дням, провайдерам и функциям смотрите там же.
9. **Свой провайдер.** «Добавить провайдера»:
   - название;
   - идентификатор (латиница);
   - базовый адрес `https://…/v1`;
   - тип: «OpenAI-совместимый» или «OpenRouter»;
   - пути chat / embeddings / rerank;
   - несекретные заголовки;
   - заметка о приватности.

   Ключ в заголовки не вписывайте: для него есть раздел «Ключи».

### В админ-боте
`/providers` открывает список провайдеров. Выберите провайдера, чтобы открыть карточку, и там:
- «➕ Ключ» — бот попросит прислать ключ сообщением;
- «🔄 Заменить ключ», «✅ Проверить», «⏸ Выключить», «🗑 Удалить»;
- «➕ Модель», «🧭 Маршруты моделей», «➕ Добавить провайдера».

Как бот обращается с присланным ключом:
- Сначала **удаляет ваше сообщение с ключом** из чата.
- Затем шифрует ключ и отвечает только маской «••••abcd».
- Если Telegram не дал удалить сообщение, бот попросит удалить его вручную.

`/spend` показывает расход за сегодня и лимиты.

Опасные действия бот выполняет только после кнопки подтверждения: удаление, смена маршрута. Кнопки изменений видят только роли с правом `settings.manage`.

## Если что-то не работает

| Симптом | Причина и что сделать |
|---|---|
| Бот молчит | Запустите `go-live-check.ts`. Чаще всего вебхук не установлен (шаг 5) или его блокирует Deployment Protection (шаг 4). |
| `getWebhookInfo`: «Wrong response from the webhook: 401» | Секрет в Vercel не совпадает с тем, с которым ставили вебхук: снова запустите `set-webhooks.ts`. Если 401 от Vercel — выключите Deployment Protection. |
| Вебхук отвечает 503 | На деплое нет токена или секрета бота: задайте переменные и сделайте Redeploy. |
| «Хранение ключей недоступно: не задан SECRETS_ENCRYPTION_KEY» | Задайте ключ в Vercel и сделайте Redeploy. |
| Ключ «не удаётся расшифровать» | `SECRETS_ENCRYPTION_KEY` поменяли: верните прежнее значение или заново введите ключи провайдеров. |
| Бот отвечает «нет доступа» | У аккаунта нет staff-роли, или Telegram привязан к другому профилю. Привяжите заново в «Уведомлениях». |
