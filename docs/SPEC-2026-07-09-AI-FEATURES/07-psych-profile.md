# 07 · Часть I / E3 — Психопрофиль фаундера (H1 база из Step 10 · S-M→M · 🔥🔥)

**Граница (жёсткая):** это бизнес-психологический / лидерский / HR-профиль. Никаких медицинских,
психиатрических или клинических диагнозов, шкал депрессии/тревожности, ярлыков личности как
болезни. Все тексты — про *поведение в бизнесе*, не про личность как таковую. Пользователь
контролирует данные: явное согласие, просмотр, сброс, удаление.

## 1. Что уже есть (Step 10 анкеты — подтверждено аудитом)

`components/onboarding/steps/Step10PersonalForm.tsx` собирает: мотивацию (`s10_why_opened`),
результаты/видение (`s10_best_result_*`, `s10_company_vision_*`), атрибуцию проблем
(`s10_who_to_blame`, `s10_problems_faced`), оценку команды (`s10_dept_assessment`,
`s10_what_depts_lack`), рыночное самовосприятие (`s10_competitor_comparison`,
`s10_brand_perception`), **делегирование**: `s10_hours_on_ops` (число), `s10_delegation_ready`
(слайдер 1–10), `s10_what_stops_delegating` (текст). Хранится в `survey_answers`.
Гигиена: заголовок шага в `step-config.ts:19` («Диагностика потерь») не соответствует форме —
исправить на «Вы как собственник».

**MVP (в составе AI-1):** интерпретатор существующих `s10_*` → базовый профиль (5 из 15 блоков:
стиль принятия решений — частично, делегирование, мотивация, стадия, ограничивающие паттерны из
текстов) + карточка профиля + `recommended_agent`. **Полный раздел (AI-2):** остальные блоки +
5 интерактивных механик.

## 4. Интерактивные механики (5 шт., AI-2)

### M1 — Ситуационный тест «Одна неделя фаундера» (стиль решений)
- **Цель:** decision-making profile (скорость/данные/интуиция/консенсус).
- **Сценарий:** 6 карточек-ситуаций (упал ключевой клиент; сотрудник просит повышение;
  конкурент снизил цены…), 4 варианта реакции каждая — варианты соответствуют стилям
  (данные / скорость / делегирование / консенсус).
- **Вход:** выборы + время ответа (грубое: быстрый/вдумчивый).
- **Расчёт:** частоты по осям → доминирующий + запасной стиль; детерминированный скоринг
  (карточка→веса в матрице), без LLM.
- **Влияние:** `decision_style` теги → формат ответов ГРИ (данные-первый ↔ вывод-первый),
  рекомендация персоны (данные → careful_analyst).
- **Риски/ограничения:** ситуации только деловые; никакой оценки «правильности» (нет
  «вы ответили плохо») — только стиль; результат можно скрыть из профиля.

### M2 — Шкала риска «Три ставки» (отношение к риску)
- **Цель:** risk profile (расчётливость vs аппетит).
- **Сценарий:** 3 виньетки с выбором распределения условного бюджета между
  безопасным/умеренным/агрессивным вариантами (слайдеры сумм) + 2 вопроса о прошлых решениях.
- **Расчёт:** средневзвешенная позиция + консистентность (разброс между виньетками) → 
  `risk_attitude: averse|calculated|seeking` + `risk_consistency`.
- **Влияние:** дефолт-персона (seeking → показывать bold_achiever с оговорками, averse →
  careful_analyst); тон подачи рисков (aversе — сначала страховка).
- **Риски:** не интерпретировать как финансовую компетентность; дисклеймер «стиль, не оценка».

### M3 — Тренажёр делегирования «Разгрузи неделю» (упр. зрелость)
- **Цель:** уточнить готовность делегировать против декларируемой (`s10_delegation_ready`).
- **Сценарий:** список из 10 типовых задач владельца (из s10_hours_on_ops-контекста) →
  перетащить в «делаю сам / делегирую / автоматизирую / не делаю»; на «делаю сам» — вопрос «что
  мешает передать?» (мультиселект страхов).
- **Расчёт:** % удержания, паттерн страхов (`control|quality|no_people|cost`).
- **Влияние:** NBA-буст задачам делегирования; coach-персона получает конкретные
  страхи для работы; блок 6 радара.
- **Риски:** не стыдить «вы всё держите» → формулировка «потенциал разгрузки: 14 ч/нед».

### M4 — Кризисный сценарий «Чёрная пятница наоборот» (давление/конфликт)
- **Цель:** реакция на неопределённость и давление (порядок действий, не «стрессоустойчивость»).
- **Сценарий:** развилка из 4 шагов (выручка -40% за месяц): каждый шаг — выбор из 3 действий,
  следующий шаг зависит от выбора (мини-дерево 3×4).
- **Расчёт:** путь → теги `crisis_first_move: cut|sell|analyze`, `communication_under_pressure:
  informs|hides|delegates`.
- **Влияние:** crisis_operator адаптирует первые рекомендации под привычный паттерн (и мягко
  показывает слепую зону: «вы сначала режете косты — проверьте, не режете ли рост»).
- **Риски:** явно игровая рамка («тренажёр, не тест»); без «правильных ответов».

### M5 — Тренажёр приоритизации «10 дел — 3 слота» 
- **Цель:** стиль фокусировки (важное/срочное/чужое).
- **Сценарий:** 10 карточек дел (из реального контекста: NBA-кандидаты, задачи плана, CRM) →
  выбрать 3 на завтра; ГРИ сравнивает с «весами» системы и обсуждает расхождения.
- **Расчёт:** совпадение с системными приоритетами + категории выбранного.
- **Влияние:** калибровка подачи NBA (если пользователь системно игнорирует продажи —
  reason-тексты делаются конкретнее, НЕ настойчивее); материал для коуч-сессии.
- **Риски:** система не «права по умолчанию» — расхождение подаётся как разговор, не ошибка;
  реальные данные пользователя не покидают его контекста.

## 5. Выходной результат: архетипы и JSON-схема

Founder archetype — 1 из 8 (совпадают по осям с персонами, но названы по-человечески и
**не оценочно**): Систематизатор, Первопроходец, Хранитель, Штурман, Пожарный, Наставник,
Казначей, Изобретатель. Правило присвоения: максимум по осям радара + tie-break по мотивации.
Архетип — «линза», не ящик: в UI всегда «ведущий стиль», с «в кризисе вы ближе к…».

## 6. Хранение, обновление, согласие, безопасность

- **Миграция 047:** `founder_psych_profiles` (user_id PK/уникальный, version int,
  answers jsonb — сырые ответы механик, result jsonb — схема выше, updated_at) +
  `user_consents` (id, user_id, kind, granted boolean, granted_at, revoked_at, text_version) —
  общая таблица согласий (используется также C1/B3/G4).
- RLS: strictly self (эксперт/админ НЕ видят психопрофиль — privacy level выше остальных данных;
  исключение возможно только новым явным consent).
- **Обновление:** пересчёт при завершении блока/механики; «Обновить профиль» раз в квартал —
  nudge (не форс); версия хранится, история не копится (последняя + prev для diff).
- **В промпты ГРИ идёт НЕ сырьё**, а один абзац: `personalization_tags` + `recommended.tone` +
  `warnings_for_ai` (граница как у `serializeSnapshot`). Сырые тексты ответов — никогда.
- **Сброс:** кнопка → удаление строки + тегов; consent revoke → персонализация выключается,
  профиль скрывается (данные удаляются по явному запросу — полное удаление, тест 13).
- LLM-интерпретатор (блок 13) — только с consent, structured output, validator запрещает
  диагнозоподобные формулировки (категория psychological risk, файл 08).

## 7. Связи

NBA (модификаторы <±10), Named Agents (recommended_agent + дефолт-тон), 90-day plan (формат
подачи задач), чат A1 (personalizationBlock), симулятор (риск-подача сценариев), дайджест
(тон вводной фразы).

## 8. Тесты

1. Без consent — раздел показывает только экран согласия; теги в промпт не попадают (обяз. 3).
2. LLM-гипотеза без подтверждения пользователя не влияет на персонализацию.
3. «Диагностируй меня» в любом месте → шаблон Т10 (обяз. 4).
4. Сброс профиля обнуляет промпт-блок немедленно.
5. Эксперт не может прочитать чужой психопрофиль (RLS-тест).
6. Схема result валидируется (Zod-зеркало JSON-схемы), битый result → профиль «не рассчитан», не 500.
