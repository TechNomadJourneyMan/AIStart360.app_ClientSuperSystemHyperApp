# 03 · Пакет II «Доверие и методология» (B1–B4)

Предпосылка из аудита: GRI-движков четыре, шкалы 0–10/0–100/0–1000 сосуществуют, `GriReport`
показывает нулевые блоки как реальные, trustScore — константа. Прежде чем «объяснять методологию»,
надо, чтобы она была одна наружу. **Решение (требует подтверждения, Q1):** канон для пользователя —
Engine B (62 критерия, 0–10, `gri_assessments`); Engine A остаётся внутренним ядром mini-GRI и
ai-scanner (0–100 не показываем рядом с 0–10 без подписи); легаси `GriReport`-блоки скрыть из
giga-panel/owner-страниц до починки (они всегда 0 — это фейк, аудит §GriReport).

## B1. Страница «Как считается GRI» (H1/M2 · S-M · 🔥🔥)

### Структура страницы `/methodology` (публичная, `app/(public)/methodology/page.tsx`)

1. **Что такое GRI** — Growth Readiness Index, диагностический индекс готовности бизнеса к росту.
   Микрокопия: «GRI — это термометр, а не приговор. Он показывает, где бизнес теряет силу, — чтобы
   вы знали, куда смотреть в первую очередь».
2. **Из чего состоит** — 7 блоков (Бизнес-модель, Денежная устойчивость, Продукт и спрос, Операции,
   Команда, Готовность собственника, Доверие и позиционирование) × 62 критерия; каждый критерий
   оценивается 1–10; блок = среднее критериев; GRI = среднее блоков. Схема-инфографика.
3. **Какие данные используются** — ваши ответы диагностики, анкета (12 шагов), финансовые данные,
   документы, CRM-активность. Что НЕ используется: данные других пользователей — без анонимной
   агрегации и без вашего согласия.
4. **Шкала** — 0–3.9 красная зона («рост опасен: сначала фундамент»), 4–6.9 жёлтая («расти можно,
   узкие места известны»), 7–10 зелёная («готовы к масштабированию»). Цель калькулятора 8.5 —
   ориентир, не норматив.
5. **Ограничения методологии** (честный блок, обязательный): самооценка субъективна; индекс
   отражает введённые данные («мусор на входе — мусор на выходе»); отраслевые различия сглажены;
   GRI — инструмент диагностики, а не аудит и не гарантия результата.
6. **Как часто пересчитывать** — полная диагностика раз в 90 дней; недельный пульс — 2 минуты
   между диагностиками.
7. **Как связаны GRI ↔ Точка А ↔ Точка Б ↔ План 90 дней** — конвейер: Точка А (где вы) →
   GRI (готовность к росту) → Точка Б (куда идёте) → План (как) → Пульс (движемся ли).
8. **Про доверие к данным** — что такое trustScore/полнота данных (B2), почему честнее показать
   «нет данных», чем цифру.
9. FAQ (5–7 вопросов) + CTA «Пройти бесплатный mini-GRI».

## B2. Честный Trust-блок (H1 · S · 🔥🔥)

### Текущее (подтверждено)

`lib/gri/logic.ts:100-101` — `const trustScore = 50;` («Placeholder for qualitative analysis»),
входит в среднее 7 блоков → систематически искажает Engine A (mini-GRI, ai-scanner).
Отдельно: `GriReport.trustScore` (Prisma) всегда 0 — писатель не заполняет блочные поля.

### Новая формула `lib/gri/trust.ts`

Два уровня, оба без выдумывания:

**Уровень 1 — «Доверие к данным» (data confidence, показывается всегда):**

```ts
export interface TrustSignals {
  surveyCompletion: number|null      // 0..1, computeCompletion() — есть
  hasFinancials: boolean             // s9n_revenue_2024 или s2_revenue_* заполнены
  financialsConsistent: boolean|null // маржа в [-100..100], выручка>0 и т.п. (deterministic.ts уже умеет)
  documentsCount: number             // document_summaries
  hasCrm: boolean                    // crm_integrations или crm_clients>0 [DEP]
  hasMetrics: boolean                // metrics materialized
  griHistoryCount: number            // gri_assessments всего
  dataFreshnessDays: number|null     // возраст текущего assessment
  marketConfirmedCount: number       // market_analysis_answers status='confirmed'
}
export function computeDataConfidence(s: TrustSignals): { score: number; level: 'low'|'medium'|'high';
  missing: string[] } | null
// null, если сигналов < 3 (не притворяемся)
// score = 100 * Σ(weight_i * signal_i);  веса: completion .30, financials .20, consistency .10,
// documents .10 (cap 3 шт), crm .10, metrics .05, history .05, freshness .05 (<90д), market .05
```

**Уровень 2 — блок GRI «Доверие и позиционирование» (Engine A):** вместо константы —
`null`, если качественных ответов нет; если есть mini-набор (`s5_usp`, `s5_has_competitor_analysis`,
`s5_target_audience`, отзывы/бренд из trust-positioning калькулятора) — считаем по ним:

```ts
// lib/gri/logic.ts — замена строк 100-101
const trustScore = computeTrustBlock(a) // number | null
// calculateGri: score = mean(блоки, где значение != null); GriResult.trustScore: number|null
// + GriResult.blocksUsed: количество учтённых блоков (для честной подписи)
```

`computeTrustBlock` для mini-GRI вернёт `null` всегда (6 вопросов не покрывают доверие) — и это
правильно: mini-GRI уже показывает только 3 блока.

### Graceful fallback и UI-тексты

- `null` → бейдж «Нет данных» серым + tooltip: «Мы не оцениваем этот блок, пока нет ответов о
  бренде, отзывах и позиционировании. Заполните раздел “Маркетинг” анкеты — и блок откроется»
  (+unlock-событие C4 при заполнении).
- Data confidence виджет у индекса: «Доверие к данным: среднее (61%). Не хватает: финансовые
  документы, CRM» — список `missing` кликабелен.
- **Запрещено:** дефолт 50, любые «приблизительно рассчитанные» значения без сигналов, изменение
  исторических записей (пересчёт только вперёд).

### Миграции

MVP — без миграций (расчёт на лету). Опционально 050: `gri_trust_signals` (user_id, snapshot jsonb,
computed_at) для истории/дайджеста — отложить до C1.

### Тесты и safety notes

1. `calculateGri` при `trust=null` усредняет по 6 блокам; сумма не «проседает к 50» (регресс).
2. `computeDataConfidence` при <3 сигналах → null → UI «нет данных» (тест 19 из обязательных).
3. Снапшот-тест: старые входы Engine A с полными ответами дают score без скачка >±5 после замены
   (кроме intended-эффекта убирания константы — зафиксировать в changelog).
4. Tooltip-тексты не обещают точность; слово «оценка», не «измерение».
5. PDF: если trust=null — строка «Доверие и позиционирование: недостаточно данных» (не 0).

## B3. Бенчмарки «вы vs топ-20% отрасли» (M2 · M · 🔥🔥)

### Существующее

`lib/point-a/benchmarks.ts` — **8 отраслей** (Розница, E-com, B2B SaaS, Услуги, Производство,
HoReCa, Образование, Медицина), медианы по 5 блокам Точки А + overall, по стадиям;
`source:'curated'`, синтетический sampleSize, `updatedAt='2026-05-19'`. Используется только внутри
scoring-v2 (percentile), пользователю блоком не показывается.

### MVP-решение

1. **Датасет v2** (тот же файл или `lib/benchmarks/dataset.ts`):

```ts
export interface BenchmarkRow {
  industry: string; stage: GrowthStage|'all'
  median: BlockScores; top20: BlockScores        // + top20 к существующей median
  source: 'curated'; sampleNote: string           // «экспертная оценка, не выборка»
  updatedAt: string
}
```

`top20` для MVP — кураторские значения (median + экспертный сдвиг), помеченные как оценки.
**Никогда** не подписывать «по данным N компаний», пока N — не реальная выборка (анти-риск
fake benchmark claims из threat model).

2. **Gap-chart** `components/benchmarks/GapChart.tsx` (recharts, уже в стеке): горизонтальные
   пары баров по 5 блокам Точки А (вы / медиана / топ-20%), gap-подпись «-2.3 до топ-20%»,
   интерпретация одним предложением на блок (детерминированный словарь).
3. **Пояснение ограничений** — обязательный блок под чартом: «Ориентиры основаны на кураторских
   оценках экспертов AIStart360 для рынков СНГ (обновлено {updatedAt}). Это не статистическая
   выборка. По мере роста анонимной базы ориентиры станут точнее» + ссылка на /methodology#benchmarks.
4. **PDF**: секция после блоков Point A (`renderPointAPdf` — новая таблица gap).
5. **Где показывать:** `/point-a` (основной), `/gri` Результат (свёрнуто), PDF. Unlock-событие C4:
   бенчмарки открываются после заполнения отрасли+стадии.

### Путь к живой базе (L3, спроектировать сейчас — включить позже)

- Таблица `benchmark_contributions` (anon): `industry, stage, block_scores jsonb, period,
  consent_id FK user_consents, created_at` — **без** user_id/company_id (однонаправленная
  анонимизация: пишем агрегируемые значения, связь с пользователем не храним; k-анонимность:
  публикация среза только при n≥25 на ячейку industry×stage).
- Согласие: отдельный consent `benchmarks_contribution` (файл 12); opt-in, отзыв прекращает
  будущие вклады (прошлые анонимны и неотзывны — сказать честно в тексте согласия).
- Джоб пересчёта перцентилей (p50/p80) → таблица `benchmark_rollups`; UI автоматически
  переключает подпись «кураторские оценки» → «по анонимным данным N компаний (n={k})».

### Тесты

1. Ячейка без бенчмарка (экзотическая отрасль) → блок скрыт, не «нулевые бары».
2. top20 ≥ median по каждому блоку (валидация датасета).
3. PDF-блок рендерится/пропускается корректно.
4. Подпись всегда содержит source-строку и дату (тест 20 из обязательных).
5. (Живая база) publish-гейт n≥25; вклад не содержит идентификаторов (интеграционный privacy-тест).

## B4. Источники под рыночными выводами (M2 · M · 🔥🔥)

### Существующее

Две поверхности: (a) Mark-analytics iframe + proxy `/api/market/[...path]` («NEVER fabricates
data», envelope `{data, meta, errors}`); (b) 50-вопросный AI-модуль `market_analysis_answers` —
уже есть поля `source ('ai'|'user'|'expert')`, `status ('draft'|'confirmed')`, `confidence`,
`model`. Нет: пользовательских цитат-источников, as-of даты в UI, confidence-легенды.

### Source data model

Расширение (миграция в пакете 054 или отдельная):

```sql
ALTER TABLE market_analysis_answers
  ADD COLUMN IF NOT EXISTS citations jsonb NOT NULL DEFAULT '[]';
-- citations: [{kind:'mark-analytics'|'survey'|'document'|'expert'|'model_reasoning',
--             label:'По данным 214 тендеров Mark-analytics', ref:'/market?tab=…'|doc_id|null,
--             as_of:'2026-07-01'}]
```

Для данных из Mark-analytics `as_of` берём из `meta` envelope прокси (`ASSUMPTION:` в meta есть
дата выгрузки — если нет, добавить на стороне Mark-analytics API и до тех пор писать дату запроса
с подписью «на момент запроса»).

### UI-паттерн цитат

- Под каждым AI-ответом рыночного модуля: строка-футер «Источник: {label} · Обновлено {as_of} ·
  Уверенность: {confidence_level}» — раскрывающаяся (полный список citations, клик → переход).
- Бейдж-легенда: `AI-черновик` (серый) / `Подтверждено вами` / `Подтверждено экспертом` —
  на основе существующих source/status.
- Правило отображения: вывод без единой citation и с confidence<0.5 рендерится с явной плашкой
  «Гипотеза модели — проверьте перед использованием», не как факт.

### AI prompt rules (генератор `lib/market-analysis/generator.ts`)

Дополнить системный промпт: «Для каждого ответа укажи citations из доступных источников
(анкета, документы, данные Mark-analytics из блока ДАННЫЕ). Если источника нет — kind:
'model_reasoning' и confidence ≤ 0.4. Запрещено ссылаться на внешние исследования, URL и
цифры, которых нет в ДАННЫХ» (существующая архитектура границы контекста сохраняется).

### Validation rules

Deterministic-слой (файл 08): (1) каждый citation.kind='document' обязан указывать существующий
doc_id пользователя; (2) 'mark-analytics' — только если данные MA реально были в контексте
генерации (флаг в input); (3) числовые утверждения без citation → downgrade confidence + плашка.

### Тесты

1. Ответ с citation 'document' на чужой/несуществующий документ отклоняется.
2. 'mark-analytics' citation без MA-данных в контексте → заменяется 'model_reasoning'.
3. as_of отображается; отсутствие даты → «на момент запроса {date}».
4. confirmed-ответы не перезаписываются генератором (регресс существующей защиты).
5. UI: вывод с confidence<0.5 без источника получает плашку гипотезы (тест 20-смежный).
