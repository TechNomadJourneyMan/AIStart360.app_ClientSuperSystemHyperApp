# Backend & API Audit — AIStart360 Portal

Date: 2026-07-07
Auditor scope: `app/api/**` (165 route.ts files) + `lib/` API-support modules.
Auth model in prod = **Supabase** (Supabase session cookie). NextAuth + Prisma models exist but are **dead for auth** (NextAuth has only a GoogleProvider, no credentials; the app never mints a NextAuth session). Postgres is shared between Prisma-owned tables and Supabase-owned tables.

ID prefix: **BE**. Severity ∈ Critical / High / Medium / Low.

---

## Summary

The API surface is large (165 routes) and shows a clear generational split: the newer `app/api/v1/**` and `app/api/giga-admin/**` routes are well built (Supabase `auth.getUser()` self-checks, per-user rate limits on paid AI, 45s OpenRouter timeouts, IDOR-safe `resolveTargetUserId`, honest "no-fabrication" fallbacks). The problems cluster in three areas: (1) **dead-auth zombie routes** — 9 routes still gate on NextAuth `requireAuth`/`requireRole` and read Prisma tables (`notification`, `client`, `report`), so in the Supabase-only app they either always 401 or read the wrong table (notifications feed, report upload, GRI-calculate, /clients CRUD are broken or duplicated by live Supabase equivalents); (2) **three overlapping admin backends** (`api/admin` Prisma+RBAC, `api/giga-admin` HMAC cookie, `api/v1/admin` Supabase) with divergent approve/reject/block semantics, inconsistent response envelopes, and one silent-success approval bug; (3) **cross-cutting hygiene gaps** — two unauthenticated paid-AI routes (`/api/gri/financial-analyst`, `/api/gri/ai-strategy`) protected only by IP rate-limit, ~25 routes leaking raw `error.message` to clients, no unified response envelope, no pagination on several admin list endpoints (full-table scans joined in JS), a non-atomic delete-then-insert in the medical audit route, and `/api/health` unauthenticated leaking env-var names. No SSRF in the market proxy (allowlist + timeout are correct). Inngest webhook signing is not configured via env, so signature verification depends on SDK defaults.

## API surface map (brief)

165 route.ts files. Namespaces:

- **`api/admin/**` (16)** — Prisma + RBAC (`requirePermission`) admin panel: requests (approve/reject/assign/comments/bulk/request-info), users (block), companies, overview, analytics, audit. Writes Prisma `adminRequest` + reconciles Supabase `profiles` via `lib/users/approval.ts`.
- **`api/giga-admin/**` (15)** — "ГИГА" super-admin, auth via HMAC-signed `aistart360_giga` cookie (`lib/giga-cookie.ts`) + **service-role** Supabase client (bypasses RLS). users, clients, requests, impersonate, market-analysis, settings/registration, 2fa-reset, widgets.
- **`api/v1/admin/**` (5)** — Supabase-session admin (`requireSupabaseAdmin`): approve-user, users/[id]/approve|reject, pending-users, clients. **These three admin namespaces overlap (BE-06).**
- **`api/v1/assistant/**` (15)** — "Гри" assistant: ask/insight/converse/analyze (paid AI, per-user throttled + timeouts), plus settings/context/status/feedback/hide/events/escalate/validate/chat/scripts.
- **`api/v1/diagnostics/**` (9)** — Point-A/Point-B diagnostics; AI routes accept signed `x-internal-token` for server-to-server fan-out (`lib/internal-auth.ts`), else Supabase session + per-user throttle. `recalculate` uses `resolveTargetUserId` (IDOR-safe).
- **`api/v1/point-a/**` (14)** — analytics reads (aggregate/segments/loss-map/retention/history/top-table/v3/benchmarks/filters), `insights` CRUD, and paid `insights/ai-generate` + `narrative` (throttled).
- **`api/v1/metrics/**` (8)** — registry/catalog/materialize + per-metric timeseries/forecast/anomalies/value/goals (Zod-validated period; deterministic compute).
- **`api/v1/security/**` (12)** — 2FA (setup/verify/challenge/disable/status), backup-codes, WebAuthn register/authenticate. (Auth internals owned by the security agent.)
- **`api/expert/**` (8)** — expert console; auth via `requireExpert` (service-role role check). Client-scoped writes (expert-cases/comments) correctly scope by `user_id`.
- **`api/clients/**` + `api/client/**` — mixed: Prisma-tenant `clients` CRUD (dead NextAuth, BE-04) vs Supabase `client/register`, `client/status`.
- **`api/gri/**` (3)** — baseline (expert), financial-analyst + ai-strategy (**unauthenticated paid AI, BE-01**).
- **`api/crm/**` (2)** — CRM integrations, org-scoped (`requireCrmOrg`).
- **`api/market/[...path]`** — server proxy to Mark-analytics FastAPI; path allowlist + 8s timeout + Supabase auth. **No SSRF.**
- **`api/pulse/**` (2)** — role-gated dashboard briefings; `/briefing` throttled (per-IP), `/pulse` calls OpenRouter per GET (no cache).
- **`api/medical/**` (4)** — clinic audit/run (non-atomic writes, BE-08), intake/validate, strategy pdf/xlsx (unbounded, BE-16).
- **`api/notifications/**` (3, dead Prisma) vs `api/v1/notifications` (live Supabase)** — BE-02.
- **`api/reports/**` (2, dead Prisma), `api/export/report`** — BE-03 / export is Supabase-based & scoped.
- **`api/share`, `api/public/mini-gri`** — share tokens (owner/staff scoped), public lead magnet (Zod + rate-limited).
- **`api/checkout`** — acquiring stub (BE-19).
- **`api/auth/**`** — register (Zod + throttled + role-safe), demo-access (throttled), NextAuth `[...nextauth]` (Google only, dead for app auth).
- **`api/dev/**` (2)** — confirm-email/register, gated to non-prod + explicit flag (correct).
- **`api/inngest`** — Inngest serve (calculateGri intentionally throws; parseDocumentFn). BE-15.
- **`api/health`** — public status (BE-12).

Backend-driven redirects: **none** — no `NextResponse.redirect` or `Location` header in any `app/api/**/route.ts`. (Login redirects are client-side; `/api/checkout` and `/api/giga-admin/impersonate` return a `url` in the JSON body for the client to navigate, not an HTTP redirect.)

## Spec notes (backend TZ items)

1. **Kill the dead-auth zombie routes (BE-02/03/04).** Any route importing `@/lib/api-utils` `requireAuth`/`requireRole` or `@/lib/auth` `auth()` is on the NextAuth path and is non-functional in the Supabase app. Inventory (9 files): `notifications/route.ts`, `notifications/read-all`, `notifications/send`, `reports/upload`, `reports/[id]`, `clients/route.ts`, `clients/[id]/route.ts`, `clients/[id]/gri/route.ts`, `clients/[id]/gri/calculate`. Decision per route: migrate to Supabase + live table, or delete. Deliverable: zero routes depend on a NextAuth session.

2. **Single approval/block service (BE-05/06/07).** All admin surfaces MUST call one function (extend `lib/users/approval.ts`) that (a) performs the `profiles` write via service-role, (b) returns `affected`, (c) returns a typed result; callers return non-2xx when `affected===0`. Remove per-namespace copies. Align giga-admin column names to the actual `admin_requests` schema.

3. **Validation policy.** Only 24/165 routes import Zod. Mandate Zod (or a shared validator) on **every** route that reads a request body or query params that drive a write. Priority: all POST/PATCH in `admin`, `giga-admin`, `v1/admin`, `medical/*`, `checkout`, `client/register`. Invalid input → `400 {ok:false,error:'invalid_input',details:<first issue>}` (never raw driver errors).

4. **Error format (BE-09).** Introduce `lib/api-response.ts` with `ok(data, meta?)` and `fail(code, httpStatus, logDetail?)`. `fail` logs `logDetail` server-side and returns only a stable `code`. Ban `error: error.message` in responses (add a lint rule / grep gate in CI).

5. **Response envelope (BE-10).** Standardize on `{ ok: boolean, data?: T, error?: string, meta?: {...} }`. 401 body uniformly `{ok:false,error:'unauthorized'}`. New routes must conform; add a test that samples routes and asserts the shape.

6. **Rate-limit policy (BE-01/13/20).** (a) No unauthenticated paid-AI route — require session; (b) all paid-AI routes: per-**user** key, ≤6/min (or 6/hour for `insight`); (c) all public write/delete routes: per-IP ≤5/min; (d) prefer platform-trusted client IP over raw `x-forwarded-for`; (e) `materialize` single-flight. Document each bucket's `{max, windowMs}` in one place.

7. **Caching.** Read-heavy deterministic endpoints (`metrics/*` forecast/anomalies/catalog, `point-a` computed reads, `market` proxy GETs) should send `Cache-Control`/use `unstable_cache` keyed by user+period. `/api/pulse` must not call OpenRouter on every GET — cache the briefing (the code comments already promise a 1-day cache that isn't implemented).

8. **Transactions & idempotency (BE-08/15).** Medical audit writes must be transactional (or insert-then-swap). Inngest `parseDocumentFn` must guard status transitions with idempotency keys; set `INNGEST_SIGNING_KEY`/`INNGEST_EVENT_KEY`.

9. **Health endpoint (BE-12).** Public output: booleans only. Detailed latency/env behind auth/internal token. Remove fabricated uptime constants or wire to a real source. Stop probing the dead `/api/notifications` route.

10. **Refactors.** Collapse the Prisma-tenant `clients/report/notification` model or the Supabase model — running both is the root of BE-02/03/04. Consider a shared `withAuth()`/`withAdmin()` wrapper so every route gets auth + rate-limit + envelope + error handling uniformly.

## Product-owner questions

1. **NextAuth/Prisma retirement:** Is there ANY remaining use of the NextAuth (Google) login or the Prisma `User`/`Client`/`Report`/`Notification` tenant tables? If not, we should delete the whole NextAuth path and the 9 zombie routes rather than migrate them. (Confirms scope of BE-02/03/04.)
2. **Three admin panels:** Which admin surface is the intended long-term one — `/admin` (RBAC), ГИГА (`giga-admin`), or the `v1/admin` REST set? We want to keep one and retire the others (BE-06).
3. **`/api/gri/financial-analyst` & `/ai-strategy`:** Are these meant to be callable by anonymous visitors (e.g. from a public landing tool), or only by logged-in clients? That determines whether we add auth or a hardened public budget guard (BE-01).
4. **Report upload:** Is client report upload a live, expected feature? It is currently broken (dead NextAuth). If live, we prioritize the Supabase migration (BE-03).
5. **Payments:** Confirmed the acquiring stub is intentional (per memory). When is real payment settlement planned, so we can schedule the signed webhook (BE-19)?
6. **Medical module:** Expected max patient rows per uploaded file? Needed to size the caps for BE-08/BE-16 (transaction + generation limits).
7. **Health endpoint audience:** Is `/api/health` consumed by an external uptime monitor that needs it public, or only by the in-app status page (which is authenticated)? Determines how much we can lock down BE-12.
