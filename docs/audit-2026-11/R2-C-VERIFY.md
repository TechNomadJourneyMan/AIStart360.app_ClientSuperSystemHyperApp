## 2. Миграция 148 (правило в `paid_section_of`)

**Безопасность** (тест-БД, текущая версия 148):

- Все функции с чтением данных — `SECURITY DEFINER`, `SET search_path = public`, владелец `postgres`. Все таблицы указаны со схемой (`public.…`), поэтому подменить их временной таблицей нельзя.
- Права на вызов (ACL после REVOKE; default privileges Supabase на тест-БД есть, и их REVOKE снял):
  - `company_rights_of`, `paid_section_of` — только `postgres`; `authenticated` → `permission denied` (проверено);
  - `paid_sections_for_owners` — `postgres` и `service_role`; `authenticated` → `permission denied`;
  - `has_paid_section` — отвечает только про `auth.uid()`;
  - `company_inherited_rights(чужой uuid)` под сессией → все `false`, без ошибки (проверено);
  - `paid_right_of` — IMMUTABLE, чистая функция без доступа к данным.
- Что клиент может узнать о других: только то, что владелец его компании платный. Это присуще решению Q3.

**Производительность** (EXPLAIN ANALYZE под `authenticated`, по 500 строк на компанию):

- `diagnostic_sessions` и `report_versions` у Free-участника Pro-компании: `InitPlan 1 → Result (rows=1 loops=1)`, фильтр `(InitPlan 1).col1 AND can_read_company(...)`. Функция считается один раз на запрос, а не на строку.
- Для Free-владельца то же: InitPlan один раз, 500 строк отфильтрованы.
- `paid_sections_for_owners`: один вызов (`Function Scan loops=1`); внутри — `paid_section_of` на каждую компанию (≤100, по индексу).

**Идемпотентность:** повторное применение 148 поверх 148 даёт 0 различий: md5 определений функций, ACL, все политики `public`.

**Откат `rollback/148_*.down.sql` возвращает состояние 147:**

- после отката: из 6 функций осталась только `has_paid_section`; политик `*_paid_section` 23 (было 29); сняты ровно 6 политик отчёта, включая `diagnostic_sessions`;
- применение 147 поверх отката меняет **0** функций и **0** политик, то есть состояние совпадает с 147;
- повторное применение 148 после отката даёт ровно прежнее состояние 148, включая ACL.

Код без 148 (если код выкатят раньше миграции) не ломается: RPC падает → `readCompanyRights = null`, пометок нет.

## 3. Новые дефекты и риски, внесённые исправлениями (сначала серьёзные)

- **Н-1. Medium / риск, зависит от флага.** Мастер и hero ведут ВСЕХ Free-клиентов на `/client/onboarding/snapshot`. Это экран режима «Экспресс + блоки», который включается флагом `NEXT_PUBLIC_SURVEY_MODES` (по умолчанию только `full`). У страницы нет проверки флага, а `ModeTwoChrome` показывает переключатель режимов, вкладки «Экспресс · Снимок · Блоки» и прогресс «Минимум для Точки А».
  - Сценарий: если на Railway-проде флаг без `express`, клиент из полной анкеты попадает в рамку выключенного режима.
  - Флаг выставлялся в Vercel 2026-10-23; есть ли он на Railway, я не проверял (по правилам). Перед выкаткой нужно проверить наличие `express` во флаге или поставить проверку флага.
  - Шаг 3 мастера всё так же никогда не становится «выполнен» (`hasDiagnostic={false}`), но так было и раньше.
- **Н-2. Low (гонка).** L-5 считает продление в JS по прочитанному плану (`getEffectivePlan` → `proAssignment`) вместо атомарного `setPlan({ extendMonths })`, который выполняется в SQL под блокировкой строк.
  - Раньше «Назначить Pro на N мес.» был идемпотентным, теперь он складывается.
  - Сценарий: двое сотрудников или две вкладки жмут «Назначить Pro на 1 мес.» по одной заявке. Если второй успеет до того, как первый закроет заявку (окно — время `setPlan`, сотни мс), второй увидит «живой Pro до +1 мес.» и продлит до +2 мес.
  - Вариант исправления: для продления передавать `extendMonths`.
- **Н-3. Low (нагрузка).** Массовое «Сменить тариф → Pro» (до `BULK_MAX` = 200, параллельность 5) теперь через `setPlan` запускает для каждого клиента догоняющий платный ИИ (`catchUpPaidAi` → 2 внутренних ИИ-вызова). Ограничения параллельности нет (`fireAiFanOut`), так что на 200 клиентов это до ~400 одновременных ИИ-запросов.
  - Это правильно по смыслу: раньше ИИ не запускался вообще, и это был баг.
  - Но это всплеск нагрузки и расходов на сервере с известными OOM-ограничениями. Нужна очередь или лимит.
- **Н-4. Low (честность интерфейса).** У `set_tier` в диалоге массового действия (`UsersBulkBar.tsx:119-135`) нет пояснения, хотя теперь:
