# Раунд 3 — план (оркестратор, 2026-11-15)

Основа: аудиты R3-AUDIT-A (Точка А), R3-AUDIT-B (Точка Б), R3-AUDIT-C (реестр Раунда 0).
Цель раунда (приоритет PO): **Точка А и Точка Б работают для платного клиента**. Остальное — следующими раундами.

## Что показал аудит
- Реестр P0–P2: P1 — 22 исправлено / 12 частично / 8 открыто; P2 — 13 / 9 / 61.
- **Точка А:** балл честный, очередь пересчёта жива, пейволл работает. Но ИИ-разбор ни разу не дошёл до клиента (все попытки `failed`, причина не пишется); конвейер диагностики падает после каждого автопересчёта (`trigger:'event'`); ИИ-гипотезы 34/34 упали (и запускаются для Free); разбора, PDF и «Поделиться» нет на основной странице; GRI на странице «из 100»; эксперты в цикле не участвуют.
- **Точка Б:** код в целом исправен (1088 тестов), но на копии прода 0 планов. Путь обрывается: Free не видит раздел; «Обзор» пуст без помесячной выручки (ввести негде); 5 из 9 вкладок пусты до одобренного плана, а план собирается вручную ~8 шагами, без очереди и SLA; клиенту без назначенного человека обещают «эксперт готовит план»; ИИ-стратегия видна клиенту без эксперта; три разных расчёта (страница / PDF·«Поделиться»·чат / старейший движок).

## Волны (≤ 2 исполнителя одновременно)
**Волна 1 — Точка А (без решений PO)**
- A1 конвейер диагностики: принять `trigger:'event'` (S)
- A2 GRI на странице Точки А — шкала 0–10 (S)
- A3 гипотезы: не запускать для закрытой Точки А; причина 34/34 сбоев (S)
- A4 честные статусы: «Минимум для Точки А» = правило балла, ошибка пересчёта после отправки видна, кнопка «Повторить», документы «обрабатывается» с апреля (S)

**Волна 2 — Точка А, платная ценность (по решениям PO)**
- A5 ИИ-разбор: писать причину сбоя (`ai_error`), модель/время; показать разбор на основной странице с пометкой «ИИ»; пробные прогоны на staging (M)
- A6 PDF и «Поделиться» на основной странице (M)
- A7 путь к баллу: кнопка «Отправить анкету — получить оценку» из Точки А (M)
- A8 инструменты эксперта v4 в `/expert` для назначенных клиентов (M)

**Волна 3 — Точка Б MVP**
- B1 очередь «Pro без плана» + SLA 48 ч на подготовку + честный статус клиенту (S/M, миграция типа SLA)
- B2 ИИ-стратегия — только черновик для эксперта, клиенту не показывается (S)
- B3 черновик плана в один клик (сценарии модели + стратегия из правил с формулировками ИИ), одобрение только с рассчитанными сценариями и темпом (M)
- B4 таблица выручки по месяцам до плана (M)

**Волна 4 — один расчёт и сквозная проверка**
- B5 PDF / «Поделиться» / чат / вкладки персонала от одной модели; «Подробности» (V2) скрыть для клиента (M)
- E2E: Точка А и Точка Б на настоящей БД + браузер на staging (Pro-клиент, Admin, эксперт) (L)

**В конце раунда:** открыть видимость Точки А и Б в «Разделах» для всех (Free видит пейволл) — отдельным «да».

## Не в этом раунде
Точность расчётов Точки Б (сезонность, налоги — L2), удаление легаси (только с «да»), один кабинет (R-028), анкета (R-031), схема как в проде (R-012), мониторинг (R-018), e2e/RLS остальной платформы (R-044/045), дизайн-система, ПДн (R-043).

## Решения по умолчанию (рекомендации аудита)
- Старые анкеты «11 из 12 шагов» не считать отправленными автоматически — кнопка «Отправить анкету».
- Free-клиенту с уже посчитанной полной Точкой А открыть `point_a` индивидуально (как GRI в Раунде 2) — после проверки на проде.
- Опубликовать план Точки Б можно только с рассчитанными сценариями и выбранным темпом.
- Выручка по месяцам — во вкладке «Финмодель».
- Сравнение с отраслью подписать «ориентир не проверен экспертом», пока пороги не утверждены.
- Легаси не удалять в этом раунде.

## Процесс
Каждый пакет — с тестом, который падал бы до правки; после каждой волны tsc/lint/полный прогон/сборка + независимое ревью; staging перед продом; выкатка: бэкап → миграции → код → `PUT /api/inngest`.
