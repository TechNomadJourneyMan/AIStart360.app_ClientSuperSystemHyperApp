## R-032 (решение PO) — когда есть общий балл
- Константы (временные до утверждения экспертом) в одном месте: `lib/point-a/v4/config.ts` — `MIN_OVERALL_WEIGHT_COVERAGE = 0.6`, `OVERALL_REQUIRED_ANY_OF = ['finance','sales']`, функция `overallAllowed(blocks)`. `POINT_A_RULES_VERSION` r1 → r2 (следующий пересчёт каждой компании пишет новую Точку А).
- Движок (`lib/point-a/v4/engine.ts`): overall/stage/health = null, если правило не выполнено; блоки с данными сохраняют баллы.
- **Правило действует и при чтении**: `official.ts` (ветка v4 и ветка v1 по блокам v4) и страница Точки А (`lib/point-a/v4/state.ts` snapshotView + история) применяют `overallAllowed` к сохранённым блокам — старые снимки «100/100, масштаб» по одним операциям перестают показывать балл сразу, без ожидания пересчёта.
- Тесты: `tests/unit/point-a-v4/scoring-fixes.test.ts` (было «операции → 100/100» → теперь null; health-тест переписан на сценарий ≥60 %), `engine.test.ts`, `summary.test.ts`, `snapshot.test.ts` (фикстуры), новый `tests/unit/point-a-v4/r032-overall-rule.test.ts` (golden + 13 случаев).
- **Сколько типичных сценариев теряют балл** (шаблон «Универсальный», 7 сценариев из фикстур): **4 из 7** — CURRENT_TYPICAL (шаги 1,2,4,9,12 — «типичный клиент текущей анкеты»: финансы+операции+стратегия = 50 % веса), «только операции», «только финансы», «финансы + операции» (40 %). Сохраняют: полная анкета (82 %), LEGACY_STRONG, LEGACY_WEAK (67 %). По отраслевым шаблонам CURRENT_TYPICAL сохраняет балл только в «Производстве» (ровно 60 %). **PO стоит знать: типичный клиент без шага продаж/маркетинга теперь видит «Балл появится, когда данных хватит».**
