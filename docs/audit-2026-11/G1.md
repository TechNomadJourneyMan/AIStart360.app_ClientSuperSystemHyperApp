# G1 — R-036: одна шкала GRI (0–10) и одна функция форматирования

Исполнитель: G1 (BI Expert + Frontend), Раунд 1. Не закоммичено (часть правок попала в WIP-чекпоинт оркестратора 38a34ce3).

## 1. Инвентаризация (откуда разные числа)

**Каноническая формула — уже 0–10.** `lib/gri-assessment/score.ts`: `computeSectionAvgs` (среднее отвеченных критериев 1–10 в секции, 0 = не отвечено) → `computeGriIndex` (среднее секций с данными, 2 знака). Пишется в `gri_assessments.gri_index` / `section_avgs` через `POST /api/v1/gri/assessment`. Официальная строка — `is_current = true` (иначе самая новая).

| Источник «GRI» | Шкала | Что это на самом деле | Где показывалось |
|---|---|---|---|
| `gri_assessments.gri_index` (канон) | 0–10 | GRI | /gri, дашборд клиента, GIGA User360/GRI, портфель, письма, ИИ |
| `lib/gri/mini.ts` (`calculateGri`, 3 блока + бонус 12) | 0–100 | экспресс-оценка (лид-магнит) | /gri-free «62 / 100», письмо «Ваш GRI: 62/100», GIGA «Лиды» |
| `diagnostics.overall_score` | 0–100 | **Точка А, не GRI** | эксперт: «Средний GRI 18.5», «GRI < 40», колонка «58 / 87 / 2»; /clients/[id] «Current GRI Score» (= overall/10) |
| Prisma `GriReport.score` (мёртвая таблица) | 0–100 | legacy | /analytics «Avg GRI» ×10 (→ «650»), /insights ÷10 |
| `lib/portfolio-gri.ts` | 0–10 | GRI | staff-дашборд «7.40 / 10» (2 знака) |
| GRI-PDF (`lib/reports/pdf.ts` ← export/report) и публичная ссылка `/r/[token]` | 0–10 ×10 → 0–100 | GRI | «Общий индекс GRI 62/100», блоки «/100» |
| Точка Б `target_overall_score` | 0–100 | **цель Точки А** | «Целевой GRI 75/100» |
| Калькулятор (среднее слайдеров), `/ai-scanner` (`calculateGri`/10) | 0–10 | прогноз/what-if | уже 0–10 |

Ответы: **62/100** — Mini-GRI (0–100 движок `lib/gri/logic.ts`); **«средний GRI 18.5», «GRI < 40», «58/87/2»** — это Точка А (`diagnostics.overall_score`, 0–100) под ярлыком GRI на `/expert/dashboard` и `/expert/clients` (разброс — разные клиенты/версии движка Точки А; 18.5 = среднее этих 0–100 значений); **7.40/10** — портфельный GRI с `toFixed(2)`. Порогов цвета было 8 разных наборов (тест 3/6, калькулятор 5/7, портфель-панель 3/6 и 3/5/7/9, эксперт 4/8, Mini 40/70, GriHero 6/8, PDF 50/70…).

## 2. Решение

- `lib/format/gri.ts` (client-safe): `GRI_SCALE_MAX=10`, **`GRI_ZONES`** — единственная константа порогов: <4 «Критично» (red), 4–6 «Развивается» (amber), 6–8 «Устойчиво» (green), ≥8 «Отлично» (green) — совпадает с полосами `/api/admin/overview` и распределением портфеля; `GRI_ATTENTION_BELOW=4`; `toGri` (0/null/>10/мусор → null), **`formatGri(v, {scale, empty, allowZero})`** — 1 знак, точка, «нет данных» вместо 0; `griFromPercent` — явная конверсия 0–100→0–10; `formatGriDelta`, `griZone/griTone/griColor`, `griPercentOfScale`, `griNeedsAttention`, `meanGri`.
- `lib/gri/official.ts`: **`getOfficialGri(sb, userId)`**, `getOfficialGriMany(sb, ids)`, чистые `pickOfficialRow` / `officialGriFromRows` (current → иначе newest; 0 → null; Точка А не используется; ошибка БД — throw, не «нет данных»).
- Хранение не менялось (Mini-GRI лиды остаются 0–100 в `mini_gri_leads`, контракт API тот же) — меняется представление.
- Не-GRI переименовано: Точка А у эксперта подписана «Точка А / 100»; «Целевой GRI» в Точке Б → «Целевая оценка Точки А».
- Разделитель — точка (как во всех остальных GRI-экранах, лендинге и OG-картинке).
