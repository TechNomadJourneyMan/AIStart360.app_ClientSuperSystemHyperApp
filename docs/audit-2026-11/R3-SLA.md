**Определения (решено и описано в шапке миграции и в `policy.ts`):**

| | `pa_ai_review` (ИИ-разбор Точки А) | `plan_prep` (план Точки Б) |
|---|---|---|
| Единица работы | **текущая** строка `diagnostics` с готовым (`completed`) или частичным / прежним разбором (`failed` + текст), без `ai_reviewed_at`. `source_id` = id строки, `lineage` = клиент | компания клиента, `source_id` = `lineage` = `companies.id` |
| Кто открывает | `expert_sla_sync` (проход) и сразу `ai-analyze` (п. 2) | только скан приложения `listClientsWaitingForPlan`: правило `waiting.ts` требует модель на TypeScript. RPC `expert_sla_plan_prep` из прохода |
| Реакция | эксперт **сохранил правки** (`ai_expert_edits`). Точное время пишет маршрут проверки, проход страхует. Просто открыть страницу — не реакция: GET без побочных эффектов | открыт **черновик версии плана** (draft / in_review). «Взять себе» реакцией не считается |
| Ответ | эксперт **подтвердил** разбор (`ai_reviewed_at`) → `reviewed`, `answered = true` | **одобрена** версия плана → `approved`, `answered = true` |
| Закрыто без ответа | строка больше не текущая (`superseded`); удалена (`gone`); проверять нечего (`failed`). Пока разбор перегенерируется (`processing`), задача остаётся открытой | скан: нет доступа к Точке Б (`no_access`), модель не строит сценарии (`needs_data`), нет цели (`no_goal`) — только если над планом никто не работает (нет открытой версии). Компания удалена или у неё сменился владелец — `gone` |
| Исполнитель | экспертная работа: ответственный клиента; иначе авто-назначение наименее загруженному эксперту; иначе общая очередь SuperExpert | никто автоматически. Общая очередь + уведомление Admin / Super Admin. «Взять себе» — Admin / Super Admin |
| Часы | новая версия той же линии (например, ночной пересчёт дал новую строку) наследует часы неотвеченной предшественницы, как в 146 п. 8 | так же; клиент «ждёт» с момента, когда проход это увидел |

### 2. «Сразу» для ИИ-разбора — немедленное уведомление без дублей
**Изменение.**
- `lib/expert-sla/immediate.ts`, функция `announceAiReviewNow`. `app/api/v1/diagnostics/ai-analyze/route.ts` вызывает её после сохранения готового **или частичного** разбора. Функция никогда не бросает.
- RPC `expert_sla_open_ai_review(диагностика, p_claim = true, …)` открывает задачу ровно для этой строки.
- **Объявление захватывается при вставке** (`assign_notified_at` / `queue_notified_at` = сейчас), поэтому outbox прохода эту задачу не видит. Ключ ленты для очереди тот же, что у прохода: `expert_sla.queued:<id>`.
- Кому сообщается:
  - есть ответственный эксперт — ему одно сообщение (лента и экспертный бот);
  - авто-назначение невозможно (выключено, экспертов нет — как на проде сейчас, ответственный не эксперт, клиент не обычный) — сразу сообщение в очередь SuperExpert (если SuperExpert нет — Admin);
  - авто-назначение возможно — очередь не захватывается: эксперта назначит проход (≤ 5 мин) и сам ему сообщит. Немедленный путь auto-assign не дублирует.
- Сбой доставки: захват снимается, попытка считается (`expert_sla_mark_notified ok=false`), проход повторит.
- Попутно в `ai-analyze`: **отметка эксперта следует за текстом.**
  - Новая генерация снимает «Проверено экспертом» и правки прошлого текста. Без этого после «Повторить разбор» клиент увидел бы «Проверено» на непроверенном тексте.
  - Разбор из кэша переносит проверку и правки той строки, откуда взят текст (включая незавершённые правки). Отметку текущей строки он не сохраняет.

**Тест.**

  - одно сообщение ответственному;
  - повтор не шлёт второе;
  - сбой → захват снят, `info_attempts = 1`;
  - экспертов нет → очередь сразу; эксперт есть → очередь не захвачена;
  - SLA выключено → ничего;
  - ошибка БД не бросает.
- `tests/unit/api/ai-analyze-r3pa.test.ts`, +3 теста:
  - новая генерация очищает отметку и правки и объявляет задачу;
  - частичный разбор объявляется, неудавшийся — нет;
  - кэш переносит незавершённые правки, а не отметку текущей строки.
- Сквозной `tests/integration/db/expert-sla-r3.test.ts`: на настоящей БД сообщение одно, проход через 5 минут второго не шлёт.

### 4. План Точки Б — сигнал, очередь и статус клиенту

## Что проверить в браузере на staging (после 150 → 151 → 152)

5. «Повторить разбор» после подтверждения: новый текст снова «Черновик ИИ», появилась новая задача.
6. PDF и «Поделиться»: пометка «Проверено экспертом…» после подтверждения.

**План Точки Б (Pro-клиент с целью по выручке и данными, без плана):**

## Остаточные риски и что не сделано
- **Открытие `plan_prep` — скан приложения, а не `expert_sla_sync`.** Правило «клиент ждёт» (`waiting.ts`) требует модели на TypeScript, поэтому в SQL только закрытие и реакции, а открытие и «больше не ждёт» идут через `expert_sla_plan_prep`.
  - Скан считает модель для ≤ 30 кандидатов за проход (≤ 10 с).
  - Кандидаты читаются из ≤ 2000 целей и ≤ 5000 компаний. При большем числе компания за пределами выборки может быть ошибочно снята как `no_goal`. Для текущего масштаба это не проблема; позже нужна курсорная выборка.
- ~~Две задачи на один план во время одобрения~~ — **решено** (решение координатора/PO, см. раздел «Дополнение 1» в конце): пока открыта `plan_prep`, `plan_review` не открывается.
- **«Сразу» и авто-назначение.** Если у клиента нет ответственного, а эксперты есть, назначение и сообщение эксперту приходят с проходом (≤ 5 мин). Немедленный путь auto-assign не дублирует, чтобы не было гонок и двойных сообщений.
- **Реакция по разбору** — только сохранённая правка или подтверждение. Открыть страницу — не реакция.
- **Новая генерация снимает отметку и правки эксперта** с текущей строки: старые правки к новому тексту не подходят. Через кэш (тот же вход → тот же текст) отметка переносится.
- **В кабинете эксперта задачи плана его клиентов видны в «Очереди»**, как `plan_review` в R2, хотя ведут их Admin / Super Admin. Не скрывал, чтобы не менять поведение R2.
- **Клиент потерял платный доступ при открытой `pa_ai_review`:** задача остаётся до проверки, пересчёта или удаления. Платный доступ в SQL не проверяется.
- **Откат 152 удаляет строки задач новых источников** (история SLA по ним теряется). Разборы и планы не трогаются.
- **Не проверено в браузере:** локальный dev-сервер смотрит в прод-БД (память проекта), staging трогать нельзя. UI проверен рендером компонентов в тестах (`renderToStaticMarkup`).
- **Не делал:** бейдж-счётчик «Ждут план» в меню ГИГА; скрытие задач плана в очереди эксперта; рабочие часы (SLA календарный 24/7, как в R2).
