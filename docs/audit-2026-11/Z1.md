## Общий модуль
`lib/access/actor.ts` (новый): `resolveActor(userId)` → `{ kind: client|expert|staff, staffRole, approved, activeExpert, clientScope: all|assigned|none }` строго по 140:
- персонал — только строка `staff_roles` при `profiles.status='approved'`; legacy `profiles.role` admin/super_admin/manager/analyst без `staff_roles` = клиент;
- эксперт — `profiles.role='expert'` + approved; эксперт не approved = никто;
- скоуп как `can_read_company`: `all` — super_admin/admin/crm_manager, super_expert/support при `client_scope='all'`; `assigned` — прочий персонал с `users.sensitive` и активные эксперты (`user_assignments`); `none` — остальные (аналитик, контент-менеджер, клиенты).
- `canAccessClient`, `canAccessCompany`, `visibleClientIds`, `isExpertPortalActor` (эксперт или staff admin/super_admin). Чтения — fetch в PostgREST (модуль импортируется динамически из `lib/api-identity.ts`, который нужен клиентскому компоненту). Ошибка чтения → отказ.
