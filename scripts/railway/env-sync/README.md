# Разовый перенос переменных окружения Vercel → Railway

Переменные проекта (в том числе секреты) попадают в сервис `portal` на Railway **без участия человека**: значения не проходят через чат, git, терминал, лог или диск. Для этого запускается одноразовая сборка в проекте Vercel `aistart360app-portal` (окружение Production): в ней Vercel сам выдаёт переменные в `process.env`, а единственная команда сборки, `push-env.mjs`, отправляет их в Railway через GraphQL API (`variableCollectionUpsert`).

Запускать только после отдельного «да» владельца продукта на перенос секретов.

## Что гарантирует скрипт

- В лог идут только **количества**, **имена** (пустых, отсутствующих, исключённых, не найденных на Railway) и **коды ошибок**. Значений, токена, тел ответов и текста сообщений Railway в выводе нет: ошибка Railway может повторить запрос в таком виде (обрезанном, с другими переносами строк), который не отфильтровать, поэтому при любой ошибке печатаются только HTTP-статус, число ошибок и `extensions.code` каждой (или «без кода»), но не `message`. Ошибка сети даёт только вид ошибки.
- **Проверка записи делается самим скриптом.** После успешной записи он тем же токеном запрашивает у Railway список переменных сервиса (в ответе есть и значения), сравнивает **имена** с отправленными в памяти и сразу забывает ответ. Выводится только «Проверено на Railway: N из N» и имена, которых на Railway нет.
- Отправляются **только имена из `names.json`**. Остальное окружение сборки не читается.
- Не переносятся: имена с префиксами `VERCEL`, `TURBO_`, `NX_DAEMON`, сам `RAILWAY_ENV_SYNC_TOKEN`, а также переменные, которые задаёт сервис Railway: `PORT`, `PERSISTENT_SERVER`, `CRON_RUNNER_ENABLED`, `INTERNAL_BASE_URL`, `NEXT_MANUAL_SIG_HANDLE`, `WORKFLOW_TARGET_WORLD`, `WORKFLOW_POSTGRES_URL`, `WORKFLOW_POSTGRES_WORKER_CONCURRENCY`, `RAILWAY_DEPLOYMENT_DRAINING_SECONDS`, `RAILPACK_NODE_VERSION`. Режим `replace: false`: другие переменные сервиса остаются, одноимённые перезаписываются.
- Пустые значения не переносятся (имена выводятся как «Пропущено пустых»).
- `skipDeploys: true`: сервис после записи не передеплоится.
- Скрипт **всегда завершается с ненулевым кодом**, поэтому рабочего деплоймента Vercel не появляется:
  - код 1 и строка «Перенос завершён, сборка остановлена намеренно» — переменные записаны и найдены на Railway;
  - код 2 и строка «Перенос НЕ выполнен: …» — не выполнен (причина в той же строке, без значений). Это и сбой записи, и сбой проверки («запись выполнена, но проверить её не удалось»), и случай, когда часть имён после записи на Railway не нашлась.

## Что нужно заранее

1. **Токен проекта Railway** (Project Token) только для окружения `production` проекта `aistart360-portal`. Создаётся в панели Railway (Project Settings → Tokens). Заголовок запроса: `Project-Access-Token`. Через `railway api` (мутация `projectTokenCreate`) создать его нельзя: вход Railway CLI на это не уполномочен, Railway отвечает «Not Authorized» (проверено 2026-11-03).
2. **Токен как временная переменная Vercel** `RAILWAY_ENV_SYNC_TOKEN`: окружение Production, тип Sensitive. Значение подаётся через stdin, а не аргументом команды, например из буфера обмена, который сразу после этого очищается:

   ```bash
   pbpaste | vercel env add RAILWAY_ENV_SYNC_TOKEN production --sensitive --project aistart360app-portal --scope technomadjourneymans-projects
   printf "" | pbcopy
   ```

   `--scope` обязателен: у учётной записи две команды Vercel, и без него CLI спрашивает, какую взять.

3. **Идентификаторы Railway**: `projectId`, `environmentId`, `serviceId` сервиса `portal` (не секреты; видны в `list-services` / панели).
4. **Список имён**: `vercel env ls production`, только столбец имён, без значений.

## Временная папка

Создаётся **вне репозитория** (например, `~/tmp/env-sync`), чтобы в git ничего не попало, и удаляется после переноса. В ней ровно четыре файла.

`vercel.json`:

```json
{ "buildCommand": "node push-env.mjs", "framework": null, "installCommand": "" }
```

`push-env.mjs` — копия `scripts/railway/push-env.mjs` без изменений.

`names.json` — **только имена**, без значений:

```json
["DATABASE_URL", "SUPABASE_SERVICE_ROLE_KEY", "NEXT_PUBLIC_SUPABASE_URL"]
```

Из списка нужно убрать имена, принадлежащие Railway (перечень выше), и временный `RAILWAY_ENV_SYNC_TOKEN` (скрипт их всё равно не отправит, но в отчёте они попадут в «Не переносятся»). Отдельно просмотреть `NODE_OPTIONS`, если он есть в Vercel: на Railway он повлияет и на рантайм. Формат имён скрипт проверяет (буквы, цифры, `_`, до 256 знаков) и отвергает весь список, если запись на имя не похожа: так отсекается заведомо не имя (URL, многострочный ключ, текст со знаками препинания). Это не защита от секрета: токен или ключ из букв и цифр под формат подходит. Поэтому `names.json` составляется только из вывода `vercel env ls` (имена, без значений), а не из значений.

`railway-target.json` — только идентификаторы:

```json
{
  "projectId": "<id проекта Railway>",
  "environmentId": "<id окружения production>",
  "serviceId": "<id сервиса portal>"
}
```

Скрипт ищет оба JSON-файла **рядом с собой**, откуда бы его ни запустили.

## Запуск

Из временной папки. Сначала привязать её к существующему проекту. Без этого `--yes` создаст новый проект с именем папки, где нет ни токена, ни переменных.

**Не использовать `vercel link`**: Vercel CLI 59 вместе с привязкой сам скачивает переменные окружения в `.env.local` этой папки, то есть значения оказываются на диске (и попали бы в загрузку деплоя). Привязка делается файлом с идентификаторами, вручную:

```bash
cd ~/tmp/env-sync
mkdir .vercel
printf '%s\n' '{"projectId":"prj_tkjFsWlGTPqUt6vOjlaJ6uxeC39x","orgId":"team_xdferxvA0jNPmQ0r90px4lVy","projectName":"aistart360app-portal"}' > .vercel/project.json
ls -A                                                 # только .vercel и четыре файла, без .env*
vercel deploy --prod --skip-domain --yes
```

В `.vercel/project.json` лежат идентификаторы, не имена. Они должны совпасть с известными:

- `projectId`: `prj_tkjFsWlGTPqUt6vOjlaJ6uxeC39x`
- `orgId`: `team_xdferxvA0jNPmQ0r90px4lVy`

Если в папке появился любой файл `.env*`, **остановиться**: удалить его не открывая и только потом запускать деплой.

`--skip-domain` защищает боевой домен, даже если бы сборка прошла. Но она не пройдёт: скрипт завершается с кодом 1 или 2. В панели Vercel появится запись о деплойменте со статусом Error; трафик она не принимает, её можно удалить.

## Что искать в логе сборки

- «Перенос завершён, сборка остановлена намеренно», строки «Перенесено переменных: N» и «Проверено на Railway: N из N» — успех. Следом «Build failed» — это ожидаемо.
- «Перенос НЕ выполнен: …» — сбой, причина названа (нет токена, HTTP-статус, число ошибок и их коды, вид сетевой ошибки, имена, не найденные на Railway после записи). Исправить причину и запустить заново: повтор безопасен, запись идемпотентна.
- Если строк «Перенос …» в логе нет, команда не запускалась. Проверить настройки проекта: **Root Directory** (должен быть пустым), **Ignored Build Step** (не должен отменять сборку), а в `vercel.json` — ключи `buildCommand` и `installCommand`.

## Проверка результата

Проверка имён (спека §6.6) уже сделана скриптом: строка «Проверено на Railway: N из N» означает, что все отправленные имена найдены в сервисе `portal`, а при расхождении перечислены отсутствующие имена и код выхода равен 2. Отдельной проверки по Railway не требуется.

**Запрещено** проверять перенос любым способом, который возвращает значения переменных: MCP-инструмент Railway `list-variables`, команда `railway variables`, сырой редактор («Raw Editor») и показ значений в панели Railway. Они выдают значения открытым текстом, и каждый секрет оказался бы в чате или терминале оператора, а это ровно то, чего этот перенос избегает. Для проверки хватает вывода скрипта.

## Что не проверено

`vercel.json` без `outputDirectory` и без `package.json` разобран по коду сборщика Vercel CLI (пустой `installCommand` пропускается, `buildCommand` без `package.json` поддерживается и выполняется в корне папки), но на самом Vercel не запускался: до «да» владельца продукта обращаться к Vercel и Railway с боевыми учётными данными нельзя. `outputDirectory` не нужен: сборка всегда падает раньше проверки выходной папки. Если Vercel всё же не запустит команду, положить в папку минимальный `package.json` вида `{ "private": true }`.

## Уборка (сразу после переноса)

1. Удалить временную переменную из Vercel: `vercel env rm RAILWAY_ENV_SYNC_TOKEN production --yes --project aistart360app-portal --scope technomadjourneymans-projects`.
2. Отозвать токен проекта Railway (Project Settings → Tokens → удалить).
3. Удалить временную папку: `rm -rf ~/tmp/env-sync`. Вместе с ней уходит и `.vercel/project.json`.
4. По желанию удалить запись об ошибочном деплойменте в Vercel.
