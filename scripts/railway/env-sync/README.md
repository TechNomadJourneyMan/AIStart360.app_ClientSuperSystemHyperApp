# Разовый перенос переменных окружения Vercel → Railway

Переменные проекта (в том числе секреты) попадают в сервис `portal` на Railway **без участия человека**: значения не проходят через чат, git, терминал, лог или диск. Для этого запускается одноразовая сборка в проекте Vercel `aistart360app-portal` (окружение Production): в ней Vercel сам выдаёт переменные в `process.env`, а единственная команда сборки, `push-env.mjs`, отправляет их в Railway через GraphQL API (`variableCollectionUpsert`).

Запускать только после отдельного «да» владельца продукта на перенос секретов.

## Что гарантирует скрипт

- В лог идут только **количество** перенесённых и **имена** (пустых, отсутствующих, исключённых). Значений, токена и тел ответов в выводе нет. Ошибки Railway очищаются от значений до вывода, ошибки HTTP и сети дают только статус или вид ошибки.
- Отправляются **только имена из `names.json`**. Остальное окружение сборки не читается.
- Не переносятся: имена с префиксами `VERCEL`, `TURBO_`, `NX_DAEMON`, сам `RAILWAY_ENV_SYNC_TOKEN`, а также переменные, которые задаёт сервис Railway: `PORT`, `PERSISTENT_SERVER`, `CRON_RUNNER_ENABLED`, `INTERNAL_BASE_URL`, `NEXT_MANUAL_SIG_HANDLE`, `WORKFLOW_TARGET_WORLD`, `WORKFLOW_POSTGRES_URL`, `WORKFLOW_POSTGRES_WORKER_CONCURRENCY`, `RAILWAY_DEPLOYMENT_DRAINING_SECONDS`, `RAILPACK_NODE_VERSION`. Режим `replace: false`: другие переменные сервиса остаются, одноимённые перезаписываются.
- Пустые значения не переносятся (имена выводятся как «Пропущено пустых»).
- `skipDeploys: true`: сервис после записи не передеплоится.
- Скрипт **всегда завершается с ненулевым кодом**, поэтому рабочего деплоймента Vercel не появляется:
  - код 1 и строка «Перенос завершён, сборка остановлена намеренно» — перенос выполнен;
  - код 2 и строка «Перенос НЕ выполнен: …» — не выполнен (причина в той же строке, без значений).

## Что нужно заранее

1. **Токен проекта Railway** (Project Token) только для окружения `production` проекта `aistart360-portal`. Создаётся в панели Railway (Project Settings → Tokens). Заголовок запроса: `Project-Access-Token`.
2. **Токен как временная переменная Vercel** `RAILWAY_ENV_SYNC_TOKEN`: окружение Production, тип Sensitive. Значение подаётся через stdin, а не аргументом команды, например из буфера обмена:

   ```bash
   pbpaste | vercel env add RAILWAY_ENV_SYNC_TOKEN production --sensitive --project aistart360app-portal
   ```

3. **Идентификаторы Railway**: `projectId`, `environmentId`, `serviceId` сервиса `portal` (не секреты; видны в `list-services` / панели).
4. **Список имён**: `vercel env ls production`, только столбец имён, без значений.

## Временная папка

Создаётся **вне репозитория** (например, `~/tmp/env-sync`), чтобы в git ничего не попало, и удаляется после переноса. В ней ровно четыре файла.

`vercel.json`:

```json
{ "buildCommand": "node push-env.mjs", "framework": null, "installCommand": "" }
```

`push-env.mjs` — копия `scripts/railway/push-env.mjs` без изменений.

`names.json` — **только имена**, без значений:

```json
["DATABASE_URL", "SUPABASE_SERVICE_ROLE_KEY", "NEXT_PUBLIC_SUPABASE_URL"]
```

Из списка нужно убрать имена, принадлежащие Railway (перечень выше), и временный `RAILWAY_ENV_SYNC_TOKEN` (скрипт их всё равно не отправит, но в отчёте они попадут в «Не переносятся»). Отдельно просмотреть `NODE_OPTIONS`, если он есть в Vercel: на Railway он повлияет и на рантайм. Записи вида «не имя переменной» (не буквы, цифры, `_`) скрипт отвергает целиком: это защита от значения, вставленного в список по ошибке.

`railway-target.json` — только идентификаторы:

```json
{
  "projectId": "<id проекта Railway>",
  "environmentId": "<id окружения production>",
  "serviceId": "<id сервиса portal>"
}
```

Скрипт ищет оба JSON-файла **рядом с собой**, откуда бы его ни запустили.

## Запуск

Из временной папки. Сначала привязать её к существующему проекту. Без этого `--yes` создаст новый проект с именем папки, где нет ни токена, ни переменных:

```bash
cd ~/tmp/env-sync
vercel link --yes --project aistart360app-portal      # при необходимости добавить --scope <команда>
cat .vercel/project.json                              # projectId должен совпасть с aistart360app-portal
vercel deploy --prod --skip-domain --yes
```

`--skip-domain` защищает боевой домен, даже если бы сборка прошла. Но она не пройдёт: скрипт завершается с кодом 1 или 2. В панели Vercel появится запись о деплойменте со статусом Error; трафик она не принимает, её можно удалить.

## Что искать в логе сборки

- «Перенос завершён, сборка остановлена намеренно» и строка «Перенесено переменных: N» — успех. Следом «Build failed» — это ожидаемо.
- «Перенос НЕ выполнен: …» — сбой, причина названа (нет токена, Railway вернул ошибки, HTTP-статус и т. п.). Исправить причину и запустить заново: повтор безопасен, запись идемпотентна.
- Если строк «Перенос …» в логе нет, команда не запускалась. Проверить настройки проекта: **Root Directory** (должен быть пустым), **Ignored Build Step** (не должен отменять сборку), а в `vercel.json` — ключи `buildCommand` и `installCommand`.

Результат проверяется по Railway: `list-variables` для `portal` содержит все имена из `names.json` за вычетом исключённых и пустых. Значения при этом не читаются и не выводятся.

## Что не проверено

`vercel.json` без `outputDirectory` и без `package.json` разобран по коду сборщика Vercel CLI (пустой `installCommand` пропускается, `buildCommand` без `package.json` поддерживается и выполняется в корне папки), но на самом Vercel не запускался: до «да» владельца продукта обращаться к Vercel и Railway с боевыми учётными данными нельзя. `outputDirectory` не нужен: сборка всегда падает раньше проверки выходной папки. Если Vercel всё же не запустит команду, положить в папку минимальный `package.json` вида `{ "private": true }`.

## Уборка (сразу после переноса)

1. Удалить временную переменную из Vercel: `vercel env rm RAILWAY_ENV_SYNC_TOKEN production --yes --project aistart360app-portal`.
2. Отозвать токен проекта Railway (Project Settings → Tokens → удалить).
3. Удалить временную папку: `rm -rf ~/tmp/env-sync`. Вместе с ней уходит и `.vercel/project.json`.
4. По желанию удалить запись об ошибочном деплойменте в Vercel.
